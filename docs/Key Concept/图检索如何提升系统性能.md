## 一、检索召回率提升（Recall Improvement）

**原系统的局限**：原始的纯向量检索只能找到与查询在**语义嵌入空间中接近**的节点。如果一个事件本身的文本描述与查询不太匹配，但它与查询高度相关（比如它是某个匹配事件的**因**或**果**），向量检索会直接遗漏它。

**图增强的提升**：通过 Graph Expansion 阶段，一个向量相似度较低但通过图边（时间相邻、共现物体、共享位置、相似动作）与高相似度种子节点关联的事件，可以被"拉入"候选集。

**典型场景**：
- 查询"为什么机器人打开了冰箱"→ 向量检索可能只匹配到"打开冰箱"这一步，但图增强通过 `TEMPORAL_ADJACENT` 和 `CAUSAL` 边，把"从桌上拿起盘子"（动机事件）也拉了进来
- 查询"用了哪些工具"→ `CO_OBJECT` 边可以把散落在不同时间段但涉及同一物体的多个事件聚合起来

## 二、检索精度提升（Precision / Ranking Quality）

**原系统的局限**：纯向量相似度作为唯一排序指标，存在"语义模糊"问题——两个表面词汇相似但语境完全无关的事件可能获得高分。

**图增强的提升**：重排序公式融合了三个信号：

```
score(q, n) = α · sim_vec(q, n) + β · Σ w(e)·sim(q, neighbor) + γ · depth_bonus(n)
```

- **β 项（图邻居贡献）**：一个节点如果有很多与查询相关的邻居，它的分数会被提升。这相当于引入了**上下文验证**——不只看节点本身，还看它的"邻域"是否也与查询相关。这会：
  - **提升**：真正相关事件（它们的邻居往往也相关）
  - **压制**：表面匹配但实际无关的噪声节点（它们的邻居通常与查询不相关）
- **γ 项（深度奖励）**：鼓励返回更具体的 `EventBasedSummary` 而非过于笼统的 `GoalBasedSummary`

## 三、跨目标/跨时间段的横向关联能力

**原系统的局限**：H-EMV 的树结构是**纵向**的（L 0→L 4 自顶向下），每个事件被严格组织在其父目标下。跨目标之间的关联在树上是**断裂**的。

**图增强的提升**：图结构在树的基础上叠加了**横向连接**：

| 边类型 | 横向关联能力 |
|--------|------------|
| `CO_OBJECT` | 不同目标下涉及同一物体的事件被关联（如"拿起杯子"和"放下杯子"可能属于不同目标） |
| `CO_LOCATION` | 在同一空间区域发生的事件被关联，即使它们属于完全不同的任务阶段 |
| `SIMILAR_ACTION` | 相似行为模式被关联（如多次"切菜"操作），支持行为模式发现 |
| `CAUSAL` | 跨目标的因果链被显式建模 |

这直接回应了你导师提到的"横向语义关联敏感性不够强"的问题。

## 四、查询自适应性（Query-Adaptive Retrieval）

**原系统的局限**：无论查什么类型的问题，检索策略完全一样——计算向量相似度 → top-p 截断。

**图增强的提升**：`classify_query_intent` 实现了**查询感知的动态边类型选择**：
- 因果类查询（"为什么…"）→ 激活 `CAUSAL` + `TEMPORAL_ADJACENT` 边
- 位置类查询（"在哪里…"）→ 激活 `CO_LOCATION` 边
- 物体类查询（"用了什么…"）→ 激活 `CO_OBJECT` 边
- 通用查询 → 激活所有非因果边

这意味着系统根据查询的**意图**动态调整检索策略，而不是"一刀切"。

---

## 五、检索鲁棒性提升

**设计上的安全机制**：

1. **min_cos_sim 阈值应用在原始相似度上**（`graph_augmented_search.py` 第 296 行），确保图增强不会把原始向量相似度极低的噪声节点推高到结果中
2. **图为空时平滑退化**（第 283 行），如果没有构建图或图为空，系统无缝回退到原始向量检索，不会出错
3. **边密度控制**（`max_edges_per_node`、`max_group_size`），防止热点节点过度连接导致的检索质量下降
4. **多重评分权重可配置**（α、β、γ），可以通过消融实验找到最优配比

## 六、可解释性增强

**原系统**：返回结果只有一个向量相似度分数，用户/研究者无法理解"为什么返回这个结果"。

**图增强的提升**：
- 每条边都携带 `evidence` 字段，记录了建边的原因（如 `"shared objects: Knife, Plate"`、`"similar actions: 'PickupObject' ↔ 'PutObject'"`）
- 图的 `stats()` 方法提供可视化的统计摘要
- 理论上可以追溯某个结果被提升的原因：是因为它的哪个邻居通过什么类型的边贡献了分数
