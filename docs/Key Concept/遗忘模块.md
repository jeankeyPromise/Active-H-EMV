## 基于记忆效用的渐进式遗忘机制（Utility-Based Progressive Forgetting, UBPF）



## 一、核心思想

H-EMV 的记忆树是只增不减的。当前评测流程中，每个 `HigherLevelSummary` 被完整加载后直接喂给 LLM Agent。该模块在 `history` 加载之后、交互式树构建之前，对记忆树执行一次**离线巩固**操作——评估每个节点的效用值，然后按效用从低到高执行渐进式遗忘，减少树的规模和噪声，同时保留关键记忆。

---

**关键设计决策**：遗忘在图构建**之前**执行。这意味着：
- 遗忘后节点减少 → 图构建更快、边更稀疏
- 图增强检索在精简后的节点集上工作 → 噪声更少、精度更高
- 两个模块形成**先筛后连**的协同关系

## 三、效用函数设计

### 3.1 效用公式

对每个 `EventBasedSummary`（L 2 节点），计算效用值：

```
U(n) = α · Recency(n) + β · Uniqueness(n) + γ · Importance(n)
```

默认权重 `α=0.3, β=0.3, γ=0.4`，可通过 YAML 配置。

### 3.2 各分项详解

#### (1) Recency — 时间衰减（艾宾浩斯曲线）

衡量记忆的"新鲜程度"。越久远的事件，效用越低。

```python
def recency(node: EventBasedSummary, now_time: datetime, half_life: float = 3600.0) -> float:
    """
    基于艾宾浩斯遗忘曲线的时间衰减。
    
    R(t) = e^(-λt)，其中 λ = ln(2) / half_life
    
    Args:
        node: 事件节点
        now_time: 当前时间（TEACh 中为 question_time）
        half_life: 半衰期（秒）。默认 3600s = 1小时
                   含义：1小时前的事件效用衰减到0.5
    Returns:
        [0, 1] 的衰减值
    """
    t = (now_time - node.latest_raw.timestamp).total_seconds()
    λ = math.log(2) / half_life
    return math.exp(-λ * max(t, 0))
```

**为什么用 `question_time`**：在 TEACh 评测中，每个 question 都有一个 `question_time`（提问发生的时间点）。用它作为 `now_time` 可以模拟"此时此刻回忆过去"的场景，使得靠近提问时刻的事件效用更高——这完全符合人类记忆的时间衰减特征。

**`half_life` 参数的意义**：
| half_life | 含义 | 适用场景 |
|-----------|------|---------|
| 300 s (5 min) | 激进遗忘，只保留最近的事件 | 短期记忆模拟 |
| 3600 s (1 h) | 中等衰减，默认值 | TEACh episode 通常 ~30 min |
| 86400 s (1 d) | 温和衰减 | ArmarX 多天场景 |

#### (2) Uniqueness — 语义独特性

衡量一个事件在其兄弟节点中的"稀有程度"。高度重复的事件（如反复走来走去）效用低，独特事件（如完成一个关键操作）效用高。

```python
def uniqueness(node: EventBasedSummary, 
               sibling_embeddings: torch.Tensor,
               node_embedding: torch.Tensor) -> float:
    """
    语义独特性：节点与兄弟节点的平均余弦距离。
    
    越不像其他节点的事件越独特，效用越高。
    
    公式：Uniqueness(n) = 1 - mean(cos_sim(n, siblings))
    
    Returns:
        [0, 1] 的独特性值。越接近1越独特。
    """
    if len(sibling_embeddings) <= 1:
        return 1.0  # 唯一节点，完全独特
    
    similarities = util.cos_sim(node_embedding, sibling_embeddings).squeeze()
    # 排除自身（相似度=1.0）
    mean_sim = (similarities.sum() - 1.0) / (len(similarities) - 1)
    return 1.0 - mean_sim.clamp(0, 1).item()
```

**为什么不用聚类**：你开题报告中提到的"增量聚类算法"有两个问题：(1) 聚类后合并会破坏树结构；(2) 聚类阈值很难调。而 Uniqueness 用**连续值**代替了**离散的"重复/不重复"二分法**——它不需要判断"这两个事件是否重复"，只需要知道"这个事件和周围的事件有多不同"。信息量更大，且完全避免了合并操作。

#### (3) Importance — 结构重要性

综合多个信号判断节点的重要性：

```python
def importance(node: EventBasedSummary,
               graph: Optional[MemoryGraph] = None,
               max_degree: int = 20) -> float:
    """
    结构重要性评分，综合多个信号。
    
    Returns:
        [0, 1] 的重要性值
    """
    score = 0.0
    
    # (a) 包含用户对话 → 高重要性
    if node.latest_raw.asr_recognition:
        score += 0.4
    
    # (b) 动作状态异常（失败、中断）→ 高重要性
    action_state = node.latest_raw.current_action_state
    if action_state and not action_state.lower().startswith('succe'):
        score += 0.2
    
    # (c) 目标状态变化 → 中等重要性
    goal_state = node.latest_raw.current_goal_state
    if goal_state:
        score += 0.1
    
    # (d) 图度中心性 → 连接越多越重要
    if graph is not None:
        node_id = graph.get_node_id_for_tree_node(node)
        if node_id is not None:
            degree = len(graph.adjacency.get(node_id, []))
            # 归一化到 [0, 0.3]
            score += 0.3 * min(degree / max_degree, 1.0)
    
    return min(score, 1.0)
```

**图度中心性的巧妙之处**：这里复用了你的图增强模块的 `MemoryGraph`。一个节点如果有很多图边（共现物体多、与其他事件有因果/时间/位置关联），说明它是"枢纽事件"，不应该被遗忘。这就是**"图结构指导记忆巩固"**的核心——两个模块共享同一个图结构，但从不同角度利用它。

## 四、渐进式遗忘策略

### 4.1 三级遗忘操作

根据效用值 `U(n)` 与阈值 `θ₁`、`θ₂` 的关系，执行不同级别的遗忘：

| 级别 | 条件 | 操作 | 数据变化 | 节省空间 |
|------|------|------|---------|---------|
| **Level 0: 完整保留** | U ≥ θ₁ | 不做处理 | 保留 L 0-L 4 所有数据 | 0% |
| **Level 1: 去细节化** | θ₂ ≤ U < θ₁ | 移除 L 0 原始感知数据（图像、声音），保留 L 1 场景图的**文本表示** | `scene.raw.image = None`，`scene.raw.sound = None`，保留 `scene.nl_graph_summary` 和 `scene.raw.current_action` 等文本字段 | ~80%（图像是最大的数据） |
| **Level 2: 摘要保留** | U < θ₂ | 将整个 EventBasedSummary **替换**为一个轻量的摘要占位节点 | 保留 `nl_summary` 文本 + `range` 时间范围 + `index_content` 的文本缓存，删除 `scenes` 列表 | ~95% |

### 4.2 具体实现逻辑

```python
def apply_forgetting_level_1(event: EventBasedSummary):
    """去细节化：删除原始感知数据，保留文本摘要"""
    for scene in event.scenes:
        # 保留文本信息，删除高开销数据
        scene.raw.image = None
        scene.raw.sound = None
        # current_action, current_goal, asr_recognition 等文本字段保留
    
    # 标记已执行遗忘（用于日志和后续判断）
    event._forgetting_level = 1


def apply_forgetting_level_2(event: EventBasedSummary):
    """摘要保留：压缩为最小表示"""
    # 在压缩前缓存关键信息
    event._cached_nl_summary = event.nl_summary
    event._cached_index_content = [s for s in event.index_content if s]
    event._cached_range = event.range
    
    # 只保留最后一个场景的文本信息（用于最小 repr）
    if len(event.scenes) > 1:
        last_scene = event.scenes[-1]
        # 清空中间场景的所有数据
        event.scenes = [last_scene]
    
    # 清理最后场景的重数据
    event.scenes[0].raw.image = None
    event.scenes[0].raw.sound = None
    event.scenes[0].relations = []  # 关系列表也可以清空
    
    event._forgetting_level = 2
```

### 4.3 遗忘豁免规则

某些节点无论效用值多低都不遗忘：

```python
def is_immune(node: EventBasedSummary) -> bool:
    """判断节点是否享有遗忘豁免"""
    # 规则 1：包含用户对话的节点永不遗忘
    if node.latest_raw.asr_recognition:
        return True
    
    # 规则 2：目标状态为失败的节点永不遗忘
    # （失败经历对问答非常关键：用户经常问"出了什么问题"）
    goal_state = node.latest_raw.current_goal_state
    if goal_state and 'fail' in goal_state.lower():
        return True
    
    # 规则 3：每个 GoalBasedSummary 下至少保留首尾两个事件
    # （确保目标的开始和结束不丢失）
    # 这个在 consolidate_goal 层面处理
    
    return False
```

## 五、整体流程：`memory_consolidation` 函数

```python
def memory_consolidation(
    history: HigherLevelSummary,
    now_time: datetime,
    embedding_fn: Callable,
    graph: Optional[MemoryGraph] = None,
    # 效用函数权重
    alpha: float = 0.3,    # recency 权重
    beta: float = 0.3,     # uniqueness 权重  
    gamma: float = 0.4,    # importance 权重
    # 遗忘阈值
    theta_1: float = 0.5,  # Level 0/1 分界线
    theta_2: float = 0.2,  # Level 1/2 分界线
    # 时间衰减参数
    half_life: float = 3600.0,
    # 安全参数
    min_retain_ratio: float = 0.3,  # 至少保留 30% 的完整节点
) -> Tuple[HigherLevelSummary, Dict[str, Any]]:
    """
    记忆巩固主函数。
    
    对 history 树中的每个 EventBasedSummary 计算效用值，
    然后按阈值执行渐进式遗忘。
    
    Args:
        history: 完整记忆树
        now_time: 当前时间（用于计算时间衰减）
        embedding_fn: 文本嵌入函数
        graph: 记忆图（用于度中心性计算，可选）
        alpha/beta/gamma: 效用函数权重
        theta_1/theta_2: 遗忘阈值
        half_life: 时间衰减半衰期（秒）
        min_retain_ratio: 最低完整保留比例（安全下限）
    
    Returns:
        (处理后的 history, 统计信息 dict)
    """
```

**执行步骤**：

1. **收集所有 EventBasedSummary 节点**（复用 `_collect_events_with_goals`）
2. **批量计算 embeddings**（一次性 encode 所有节点的 `index_content`）
3. **逐节点计算效用值**：`U(n) = α·Recency + β·Uniqueness + γ·Importance`
4. **应用安全下限**：如果按阈值计算完整保留的节点比例低于 `min_retain_ratio`，动态下调 `θ₁` 和 `θ₂` 直到满足
5. **执行遗忘**：遍历所有节点，根据效用值和豁免规则执行对应级别的操作
6. **返回统计信息**：保留/去细节化/摘要保留的节点数、效用值分布等

## 六、集成点：在 `setup.py` 中的嵌入位置

在 `setup_llm_emv` 函数中，遗忘模块插入在**图构建之前**：

```python
def setup_llm_emv(cfg_path, history, now_time, ...):
    cfg = load_config(...)
    search_emb, filter_kwargs = create_search_embedding_and_cfg(cfg.pop('search', None))
    
    # ===== [NEW] 记忆巩固 =====
    forgetting_cfg = cfg.pop('forgetting', None)
    if forgetting_cfg is not None and forgetting_cfg.get('enabled', False):
        from .memory_consolidation import memory_consolidation
        history, forget_stats = memory_consolidation(
            history=history,
            now_time=now_time,
            embedding_fn=search_emb,
            # graph 此时还没构建，先传 None
            # 或者：先构建一个临时轻量图用于度中心性
            graph=None,  # 见下方"鸡生蛋"问题的讨论
            **forgetting_cfg
        )
        print(f'[Forgetting] 巩固完成: {forget_stats}')
    
    # 图增强检索（在遗忘后的精简树上构建）
    graph_cfg = cfg.pop('graph_augment', None)
    if graph_cfg is not None:
        memory_graph = create_memory_graph_cached(history, search_emb, graph_cfg)
        ...
```

### "鸡生蛋"问题：遗忘需要图，图需要树

效用函数中的 `Importance` 分项需要图的度中心性，但图是在遗忘之后才构建的。两种解决方案：

**方案 A（推荐）：两阶段构建**
1. 先用 `build_memory_graph` 构建一个**临时轻量图**（只启用 `TEMPORAL_ADJACENT` 和 `CO_OBJECT` 两种快速边，跳过耗时的 `SIMILAR_ACTION`）
2. 用这个临时图计算度中心性 → 完成效用评估 → 执行遗忘
3. 在遗忘后的精简树上构建**完整图**（包含所有边类型）

**方案 B：不用图**
- 直接去掉度中心性项，只用 `Recency + Uniqueness + 规则式 Importance`
- 工程更简单，但学术故事弱了

## 八、消融实验设计

这个模块可以支撑以下实验，覆盖毕设论文的实验需求：

### 实验 1：遗忘策略对比

| 配置 | 描述 |
|------|------|
| **baseline** | 无遗忘（完整记忆树） |
| **random** | 随机遗忘相同比例的节点 |
| **recency-only** | α=1, β=0, γ=0（只看时间衰减） |
| **uniqueness-only** | α=0, β=1, γ=0（只看语义独特性） |
| **importance-only** | α=0, β=0, γ=1（只看结构重要性） |
| **full UBPF** | α=0.3, β=0.3, γ=0.4（完整效用函数） |

**预期结论**：full UBPF 在相同遗忘比例下，对 TfD 指标的损害最小。

### 实验 2：遗忘率 vs 性能曲线

通过调整 `θ₁` 和 `θ₂`，控制实际遗忘比例从 0% 到 70%：

| θ₁ | θ₂ | 预期完整保留 | 预期去细节化 | 预期摘要保留 |
|----|----|-------------|-------------|-------------|
| 0.0 | 0.0 | 100% | 0% | 0% |
| 0.7 | 0.3 | ~40% | ~30% | ~30% |
| 0.8 | 0.5 | ~25% | ~35% | ~40% |
| 0.9 | 0.7 | ~15% | ~30% | ~55% |

绘制 **遗忘比例 (x 轴) vs BLEU/ROUGE/S_c (y 轴)** 曲线。预期效用引导遗忘的曲线衰减远慢于随机遗忘。

### 实验 3：与图增强的协同效应

| 配置 | 描述 |
|------|------|
| 基线（无图无遗忘） | 原始 H-EMV |
| 仅图增强 | 图增强检索 |
| 仅遗忘 | 效用引导遗忘 |
| 图增强 + 遗忘 | 两个模块同时启用 |

**预期结论**：两个模块协同效果 > 单独使用之和，因为遗忘减少了噪声节点，使图增强检索的精度更高。

### 实验 4：效用函数分项贡献

对比移除度中心性后的效用函数（`use_graph_centrality: false` vs `true`），验证图结构信号对遗忘决策的指导价值。

这就是完整的模块设计。核心亮点是：
1. **不做合并**，用连续的 Uniqueness 分数替代离散聚类
2. **渐进式遗忘**而非一刀切删除，保留了信息的梯度
3. **图结构指导巩固**，让模块一和模块二形成有机整体
4. **安全机制**（`min_retain_ratio`、遗忘豁免）确保不会因激进遗忘而崩溃
