### 一、核心设计思想

本质是**不动树的存储结构，只在检索管线中插入一个图索引层**。可以类比理解为：

树依然是记忆的"骨架"，图是检索的"神经网络"——骨架决定结构，神经网络决定信号怎么传播。



### 二、技术架构详解

#### 2.1 图的构建（离线阶段）

图不需要取代树，而是**从树中自动派生**出来的一层索引。每个 `EventBasedSummary`（L2 节点）作为图的一个节点，边通过规则和 LLM 混合生成：


**五类边的生成策略**：

| 边类型                 | 生成方式                     | 成本   | 示例                            |
| ------------------- | ------------------------ | ---- | ----------------------------- |
| `TEMPORAL_ADJACENT` | 规则：相邻时间窗口（< 5min）        | 零成本  | 切土豆 → 煮土豆                     |
| `CO_OBJECT`         | 规则：共享 `instance_id`      | 零成本  | 拿起 Knife_1 ↔ 用 Knife_1 切      |
| `CO_LOCATION`       | 规则：同一位置标签                | 零成本  | 厨房事件A ↔ 厨房事件B                 |
| `SIMILAR_ACTION`    | Embedding：动作向量余弦相似度 > 阈值 | 低成本  | Slice(Potato) ↔ Slice(Tomato) |
| `CAUSAL`            | LLM 推断：批量对时间相邻事件对做因果判断   | 中等成本 | Clean(Mug) ← 因为要 Pour(Coffee) |
|                     |                          |      |                               |

**前三类边是纯规则派生的，零额外成本**；第四类复用已有的 embedding；只有因果边需要 LLM 介入，而且可以在构建树的 `llm_summary` 阶段顺带完成。


#### 2.2 图增强检索

这是方案的核心——一个三阶段检索管线：

```
┌─────────────────────────────────────────────────────┐
│                  检索管线（Online）                    │
│                                                      │
│  Stage 1: Seed Retrieval（种子检索）                   │
│  ┌──────────────────────────────┐                    │
│  │  Query → Embedding           │                    │
│  │  → cos_sim with all nodes    │                    │
│  │  → Top-p / threshold filter  │                    │
│  │  → Seed Set S₀              │                    │
│  └──────────────────────────────┘                    │
│                  ↓                                    │
│  Stage 2: Graph Expansion（图扩展）                    │
│  ┌──────────────────────────────┐                    │
│  │  For each node in S₀:        │                    │
│  │    neighbors = graph[node]   │                    │
│  │    filter by edge_type       │                    │
│  │    filter by weight > θ      │                    │
│  │  → Expanded Set S₁           │                    │
│  └──────────────────────────────┘                    │
│                  ↓                                    │
│  Stage 3: Re-ranking（重排序）                         │
│  ┌──────────────────────────────┐                    │
│  │  For each node in S₀ ∪ S₁:   │                    │
│  │    score = α·sem_sim(q, n)   │                    │
│  │          + β·graph_score(n)  │                    │
│  │          + γ·structural(n)   │                    │
│  │  → Final ranked results      │                    │
│  └──────────────────────────────┘                    │
│                  ↓                                    │
│         送入 Tree Navigation + LLM                    │
└─────────────────────────────────────────────────────┘
```

**重排序公式**：

```
score(q, n) = α · sim_vec(q, n) + β · Σ_{e∈E(n)} w(e) · sim_vec(q, neighbor(e)) + γ · depth_bonus(n)
```

其中：

- **第一项**：节点 n 本身与查询 q 的向量相似度（原有能力）
- **第二项**：n 的图邻居与 q 的加权相似度之和（图增强项，新增能力）
- **第三项**：树深度奖励，优先返回更具体的节点（结构先验）
- α, β, γ 为超参数，可在验证集上调优

**第二项就是这个方案的精髓**——一个节点即使自身与查询不太相似，但如果它的图邻居中有高度相关的节点，它的得分也会被提升。这正好解决了"切土豆"和"洗杯子"这类因果关联但语义不相似的场景。
