## 反馈驱动的记忆修正与错误传播抑制

## 一、问题定义

原 H-EMV 系统的记忆摘要一旦生成便**固定不变**（`nl_summary` 是 `@property`，从底层 `RawDataInstant` 和 `SceneGraphInstant` 动态计算）。当视觉理解或 LLM 摘要出现偏差时（如将"客厅"误识别为"厨房"），错误会被"冻结"在记忆中，导致后续所有涉及该节点的问答都受影响，形成**误差传播**。

更关键的是，这类错误往往不是孤立的——如果视觉模型在某时刻误识别了场景，时间上相邻的多个事件节点很可能都受到同一错误的影响。

---

## 二、核心技术方案

### 2.1 技术难点：`nl_summary` 不可直接赋值

`EventBasedSummary.nl_summary` 和 `GoalBasedSummary.nl_summary` 都是 `@property`，从底层字段动态计算。直接赋值会抛出 `AttributeError`。

**解决方案：摘要覆盖机制（Summary Override）**

不修改底层数据结构（`scenes`、`raw`），而是在节点对象上动态挂载 `_summary_override` 属性。所有消费摘要的位置（搜索、展示）优先检查此属性：

```python
def apply_summary_override(node, corrected_summary, source=""):
    node._original_summary = node.nl_summary     # 保留原始版本
    node._summary_override = corrected_summary    # 设置覆盖
    node._correction_source = source              # 修正来源追溯
    if hasattr(node, '_embedding_cache'):
        delattr(node, '_embedding_cache')         # 强制搜索重新计算
```

相应地，系统中两个关键消费点被修改：

| 消费点 | 文件 | 作用 |
|--------|------|------|
| `history_search_similarity` | `emv_api.py` | 计算搜索 embedding 时，将 `_summary_override` 加入文本列表 |
| `ExpandableTreeNode.__repr__` | `interactive_tree.py` | 展示摘要时，优先使用 `_summary_override` |

这确保了修正后的内容既**可被搜索到**（embedding 重算），又**可被 LLM Agent 看到**（repr 更新）。

## 三、四阶段修正管线

### Stage 1：错误定位（Error Localization）

**目标**：找到"哪个记忆节点的内容导致了错误回答"。

**算法**：

1. 构造"错误特征查询" = `question + wrong_answer`
2. 构造"正确特征查询" = `question + correct_answer`
3. 对每个 `EventBasedSummary` 节点计算嫌疑度：

```
suspicion(n) = 0.6 × sim(n, error_query) + 0.4 × (1 - sim(n, correct_query))
```

**直觉**：一个节点如果与"错误信息"高度相关，同时与"正确信息"不太相关，那么它就是最可能出错的节点。

例如：问题是"机器人在哪个房间切了苹果"，错误答案"厨房"，正确答案"客厅"。包含"厨房+切苹果"但不含"客厅"信息的节点会获得最高嫌疑度。

**安全机制**：已经修正过的节点（有 `_summary_override`）自动跳过，避免重复修正。

### Stage 2：单点修正（Node Correction）

**首选：LLM 辅助修正**

```
System: "你是一个修正机器人记忆记录的助手..."
User:   "原始摘要: {nl_summary}
         用户指出: 对于问题'{question}'，正确答案应是'{correct_answer}'
         而系统错误回答了'{wrong_answer}'。
         请修正摘要，只改错误部分。"
```

**回退：简单文本替换**（无 LLM 时）

1. 在摘要中查找 `wrong_answer` 的完整匹配 → 替换为 `correct_answer`
2. 如果无完整匹配，提取差异词（如"厨房"vs"客厅"→ 差异词"厨房"/"客厅"）→ 局部替换

**修正后**：调用 `apply_summary_override` 挂载覆盖 + 清除 embedding 缓存。

### Stage 3：错误传播检测（Error Propagation Detection）

**核心洞察**：错误不是孤立的。如果视觉模型在 t=5 误识别了场景，t=4 和 t=6 的节点很可能有同样的误识别。

**算法**：

1. 从已修正节点出发，找到时间序列上的前后 `max_hops` 个邻居
2. 计算每个邻居的摘要与**原始错误摘要**的余弦相似度
3. 如果相似度 ≥ `propagation_similarity_threshold`（默认 0.7），标记为疑似传播错误

```python
neighbor._correction_hint = {
    'source_node_idx': target_idx,
    'similarity_to_error': sim,
    'original_error': original_summary,
    'correction_applied': corrected_summary,
    'reason': "时间前方第1个事件，与原错误摘要相似度=0.85"
}
```

### Stage 4：自动传播修正（Auto Propagation）

对高置信度（sim ≥ 0.8）的传播错误自动应用修正：

- **有 LLM**：用"类比修正"prompt，告诉 LLM "节点 A 做了这样的修正，请对相似的节点 B 做同样类型的修正"
- **无 LLM**：提取源修正的差异词对（如"厨房"→"客厅"），在邻居节点摘要中执行相同替换

## 四、评测协议：模拟反馈评测

### 4.1 与标准评测的区别

| | 标准评测 | 模拟反馈评测 |
|---|---|---|
| **History 隔离** | 每题 `deepcopy(history)` | 同 episode 内共享 history |
| **跨题状态** | 无 | 修正结果持久化到后续问题 |
| **反馈来源** | 无 | 用 ground truth 模拟用户反馈 |
| **启用方式** | 默认 | `--enable-correction` |

### 4.2 评测流程

```
对每个 episode:
  shared_history = deepcopy(原始 history)  // 第一个问题的 history
  
  for Qᵢ in 该 episode 的所有问题:
      Aᵢ = agent.answer(Qᵢ, shared_history)     // 用共享 history 回答
      correction_pipeline(                         // 每次都尝试修正
          shared_history, Qᵢ,
          wrong_answer=Aᵢ, correct_answer=A*ᵢ
      )
      // shared_history 可能被 in-place 修正
      // 下一个问题 Qᵢ₊₁ 将受益于此修正
```

### 4.3 Episode 分组逻辑

通过 `sample_id` 前缀判断 episode 边界：

```
sample_id = "abc123-0-sequence_of_task_descs"
                            └── episode_key = "abc123-0"
```

TEACh 的 question key 使用下划线（如 `sequence_of_task_descs`），不包含横线。`rsplit('-', 1)` 可靠地分离出 episode key。

## 五、与其他两个模块的协同

### 5.1 与图增强检索的协同

记忆图为错误传播检测提供了结构化的邻居关系。虽然当前实现使用时间序列位置查找邻居（简化方案），但可以扩展为直接复用 `MemoryGraph` 的 `TEMPORAL_ADJACENT` 和 `CO_LOCATION` 边进行更精确的传播检测。

**"一图三用"**：
- 模块一（图增强检索）：图用于**扩展检索候选**
- 模块二（效用引导遗忘）：图的度中心性用于**指导保留决策**
- 模块三（记忆修正）：图的边关系用于**追踪错误传播**

### 5.2 与效用引导遗忘的协同

被修正过的节点应获得更高的效用值（因为用户已确认其重要性）。可以在 `memory_consolidation.py` 的 `compute_importance` 中添加：

```python
if hasattr(node, '_summary_override'):
    score += 0.3  # 修正过的节点天然重要
```

correction:
  enabled: true

## 七、消融实验设计

| 配置 | 描述 |
|------|------|
| `full_graph_aug.yaml` | 基线：图增强，无修正 |
| `full_correction_only.yaml` | 仅修正，无图增强 |
| `full_correction_no_propagation.yaml` | 修正但禁用传播检测 |
| `full_graph_aug_correction.yaml` | 图增强 + 完整修正 |

**预期结论**：
1. 修正 vs 无修正：后续问题的正确率显著提升
2. 传播检测 vs 无传播：多步连续错误场景下差异最大
3. 图增强 + 修正 > 单独使用之和：图提升检索精度 → 更少的错误 → 修正更有效

## 八、论文叙事

> 针对记忆摘要"一旦生成即冻结"导致的误差传播问题，本研究提出**反馈驱动的记忆修正机制**，包含两个核心阶段：（1）**单点修正**——通过构造"错误特征向量"与"正确特征向量"的对比，精确定位出错节点，利用 LLM 生成保留原始信息的最小化修正；（2）**错误传播抑制**——利用事件的时间邻接关系，从已修正节点出发检测可能受同一感知误差影响的相邻节点，实现"从点到面"的错误修复。该机制通过"模拟反馈评测协议"在 TEACh 数据集上验证，证明了跨问题的记忆修正对后续问答质量的正向影响。
