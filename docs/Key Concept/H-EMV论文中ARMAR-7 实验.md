先纠正一个术语：论文中真实机器人实验用的是 **ARMAR-7 人形机器人**；**ArmarX** 是它所在实验室使用的机器人软件框架/认知架构实现环境，不是机器人本体。论文说 ARMAR-7 是 KIT ARMAR 人形机器人家族的新成员，真实机器人实验就是在它的家庭服务任务记录上做的。

## 1. 这部分实验到底想验证什么？

这篇论文的核心目标不是让机器人“现场执行任务”，而是让机器人在完成很多真实任务之后，能够回答关于自己过去经历的问题，例如：

> “你 7 月 12 日下午 1:30 左右说自己看到了哪些物体？”
> “你上次把牛奶带到了哪里？”
> “你今天下午最后一次抓取豆奶时，旁边是什么物体？”

所以 ARMAR-7 实验验证的是：

**真实机器人长期经历记录 → 构建层级情景记忆树 → 用户提问 → LLM 主动检索树节点和图像 → 回答过去发生过什么。**

这和 TEACh 仿真实验不同。TEACh 有较干净的状态和自动生成 QA；ARMAR-7 是实体机器人真实运行记录，数据更乱、更真实，任务规模也更小，更接近 demo + 小规模定量评估。

---

## 2. 实验数据是怎么来的？

他们让 ARMAR-7 执行多段典型家庭任务，并把机器人经历记录下来。论文说这些真实机器人 session 总计 **3.3 小时机器人动作记录**，时间跨度覆盖 **约两个月**。记录内容来自 ArmarX 记忆系统，包括：

| 数据类型    | 具体内容                          |
| ------- | ----------------------------- |
| 视觉      | RGB 图像、深度图像                   |
| 机器人自身状态 | proprioception，即关节、平台位姿等机器人状态 |
| 技能事件    | 已执行动作、目标、技能调用                 |
| 语言      | 语音识别结果 STT、机器人语音输出 TTS        |
| 符号场景    | 物体及其关系，例如对象、空间关系等             |

论文明确说，他们记录了 ArmarX 记忆系统中的条目，包括 vision、robot state、skill events、speech、symbolic scene；然后基于这些记录构建 history tree。 ArmarX 记忆系统本身被设计为机器人认知架构中的核心组件，支持多模态表示、关联知识、情景结构和长期存储。([arXiv][1])

## 3. 真实机器人记录如何变成 H-EMV 的“层级记忆树”？

ARMAR-7 实验中，论文将真实机器人记录组织成一个多层结构：

| 层级                 | 在 ARMAR-7 实验中的含义                |
| ------------------ | ------------------------------- |
| L0 Raw Experiences | 图像、语音、机器人自身状态等原始经历              |
| L1 Scene Graphs    | 来自 ArmarX 的符号场景信息：物体及其关系        |
| L2 Events          | 低层动作事件，例如具体技能动作                 |
| L3 Goals           | 高层目标/复合动作；L3 可以嵌套，因为一个目标可能包含子目标 |
| L4+ Summaries      | LLM 递归生成的更高层摘要，把大量事件进一步概括       |

这里有一个关键点：在 TEACh 或 Ego4D 中，很多 scene graph 信息要靠视觉模型推断；但在 ARMAR-7 上，ArmarX 框架本身已经有符号场景组件，所以 L1 scene graph 可以直接利用机器人系统已有的语义场景信息。论文在方法部分也说，真实机器人实验中 scene graph 使用 ArmarX 软件框架中已有的语义场景信息。

此外，真实机器人动作参数可能非常长、非常细，所以他们在 real-robot 实验中额外用 LLM 过滤和总结 raw action parameters，否则动作记录会过于冗余。L3 层允许 goal 节点包含 event 或其他 goal 节点，这正是为了表示复杂任务的子目标结构。

## 4. 用户提问时，系统是怎么查记忆的？

查询阶段不是把全部历史一次性塞给 LLM，而是让 LLM 像 agent 一样“操作”记忆树。初始时，整棵树是折叠的，LLM 只能看到高层摘要。然后它可以调用工具：

| 工具/动作                  | 作用               |
| ---------------------- | ---------------- |
| `expand(date/time)`    | 展开某个日期或时间附近的节点   |
| `search("关键词")`        | 在某个节点下做语义搜索      |
| `collapse`             | 收起无关节点，节省 token  |
| `vqa(question, image)` | 调用视觉语言模型查看叶子节点图像 |
| `answer()`             | 最终回答问题           |

论文给出的示例是：问题问“昨天 3 点左右你抓取的牛奶包装是什么颜色？”LLM 先展开相应日期，再搜索 “grasp milk”，再展开具体时间段，最后调用 VQA 查看图像并回答“绿色和白色”。论文强调，LLM 可以调用索引搜索、VLM/VQA 或执行其他计算来收集信息。

这个设计的意义是：**LLM 不需要读完整两个月历史，只需要逐层缩小范围，最后在必要时查看原始图像。**

## 5. QA 样本怎么设计？

论文没有在 ARMAR-7 上自动生成大规模 QA，而是人工标注了 **30 个 QA pairs**，然后运行 H-EMV，并手动分类结果。评价仍然使用 `S_c` 和 `S_p`：

| 指标    | 含义                               |
| ----- | -------------------------------- |
| `S_c` | 严格正确率：完全正确、正确摘要、正确但信息过多          |
| `S_p` | 至少部分正确率：包含完全正确 + 部分正确            |
| `T`   | 平均 prompt token 数，以 1K token 为单位 |

论文的评价标准说明，`S_c` 是 correct samples 的比例，`S_p` 是 at least partially correct samples 的比例，并且 `C ⊆ P`。

## 6. 结果表怎么读？

ARMAR-7 的结果在 Table II 右半部分。原表如下：

| 方法     |   层级 | LLM    | `S_c` | `S_p` |  `T` |
| ------ | ---: | ------ | ----: | ----: | ---: |
| 1-pass | flat | Gemini |    43 |    53 |  227 |
| H-EMV  |   L3 | Gemini |    40 |    70 | 29.2 |
| H-EMV  | full | Gemini |    33 |    73 | 10.5 |
| H-EMV  |   L3 | GPT-4o |    30 |    47 | 68.4 |
| H-EMV  | full | GPT-4o |    43 |    70 | 12.8 |

论文表明，ARMAR-7 的 1-pass Gemini baseline 可以直接访问完整的 episodic data stream，但不包括图像；它取得 `S_c=43`、`S_p=53`、`T=227`。相比之下，H-EMV full + Gemini 的 `S_c=33` 较低，但 `S_p=73` 更高，而且 token 成本只有 `T=10.5`；H-EMV full + GPT-4o 则达到 `S_c=43`、`S_p=70`、`T=12.8`。

换句话说：

| 角度            | 结论                                                       |
| ------------- | -------------------------------------------------------- |
| 严格正确率 `S_c`   | H-EMV full + GPT-4o 与 1-pass Gemini 持平，都是 43%            |
| 至少部分正确率 `S_p` | H-EMV full + Gemini 最高，达到 73%                            |
| token 成本      | H-EMV full + Gemini 最低，10.5K；相当于 1-pass baseline 的约 1/21 |
| 综合效果          | full 层级树比只到 L3 更稳定，尤其在 token 成本上明显更低                     |

论文自己的总结是：交互式层级系统取得了更好的 `S_p`，`S_c` 略低，但只用了约 **1/21** 的 token 成本；而 full system + GPT-4o 给出了最好的整体结果。

## 7. 具体成功、部分正确、失败案例

论文 Fig. 5 给了三个 ARMAR-7 真实实验 trace。

第一个是成功案例。问题是：

> “What objects did you detect when telling what you can see at July 12 around 1:30 PM?”

系统先展开 `2024/07/12 13:30` 附近的节点，再展开子节点，最后回答：

> apple tea, Nesquik, milk, vanilla cookies

ground truth 也是这些物体，所以判为正确。

第二个是部分正确案例。问题是：

> “Where did you last bring the milk at July 12?”

系统回答说当天两次把牛奶带给人，一次来自 sideboard，一次来自 unspecified location；但 ground truth 是 **15:21 在 home location 把它交给了 human**。因此它抓住了“带牛奶给人”这个大事件，但没有准确回答“最后一次在哪里”，属于部分正确。

第三个是错误案例。问题是：

> “Which object was next to the soy milk last time you grasped it today in the afternoon?”

系统展开了 8 月 27 日的节点，并调用 VQA 问图像里豆奶旁边是什么，回答 “sink”；但 ground truth 是 “orange juice bottle”。论文说明这个错误是因为模型展开了错误节点，并没有找到“最后一次抓取牛奶/豆奶”的那次事件。

## 8. 为什么 H-EMV 在真实机器人上有优势？

核心优势不是准确率碾压，而是 **可扩展检索 + 低 token 成本 + 可解释 trace**。

1-pass baseline 的做法是把完整历史直接给 LLM。优点是不会因为“展开错节点”而漏信息；缺点是 token 极高，历史越长成本越爆炸，而且长上下文里信息容易被淹没。

H-EMV 的做法是从高层摘要逐步向下查。它的优点是可以处理更长历史，并且每一步检索路径可解释；缺点是如果高层摘要太粗、树构建有误、LLM 搜错节点，就会错过关键信息。论文也明确说，LLM 可以展开/折叠节点、做语义搜索、调用 VQA，并通过这种交互式方式找到相关信息。

## 9. 失败原因是什么？

论文的 failure analysis 很重要。对 ARMAR-7 和 Ego4D 的真实世界实验，他们人工检查了 Gemini 版本 H-EMV 的错误或部分错误 trace，并把失败归因到三类：

| 失败来源             | 含义                       |
| ---------------- | ------------------------ |
| EM construction  | 记忆树构建本身有问题，例如摘要过粗、误导     |
| EM retrieval     | LLM 没有展开到正确节点，或者没有展开得足够深 |
| LLM QA reasoning | 已经找到相关信息，但推理或调用 API 失败   |

在 ARMAR-7 上，论文说 **20 个失败样本中有 19 个与 retrieval 有关**。这说明真实机器人场景下，最主要瓶颈不是“LLM不会说话”，而是 **如何在深层嵌套的长期记忆树中找到正确节点**。论文还指出，ARMAR-7 的树非常深，因此检索尤其困难；另外也有 7/20 个失败样本涉及树构建问题，例如 LLM 生成的摘要太宽泛或具有误导性。
