# 遗忘模块实验设计（ARMARX_LT_MEM）

## 1. 先说结论

在当前项目条件下，**没有 ARMAR-7 原始照片/语音文件并不意味着遗忘模块无法验证**。  
但实验目标需要表述准确：

- **不能过度宣称**：我们不能直接证明“删除真实底层多模态大文件后系统仍然有效”，因为当前可获得的数据是 `data/armarx_lt_mem/*.pkl`，而不是原始长期日志仓库。
- **可以有说服力地证明**：在真实机器人实验配套发布的长期记忆树上，遗忘机制能够：
  1. 压缩层级记忆表示；
  2. 保留较强的问答能力；
  3. 相比随机遗忘更合理；
  4. 明确揭示哪些问题类型更依赖底层细节，哪些问题只需要高层摘要。

因此，论文中对该模块最稳妥、最有说服力的定位应是：

> 我们在 ARMAR-7 配套发布的长期记忆树数据上，对“效用引导的层级记忆压缩/遗忘”进行了受控验证。虽然无法直接访问真实机器人原始照片与语音仓库，但仍可在已发布的 episodic memory tree 上定量考察遗忘前后在存储规模、树复杂度和问答正确率之间的权衡关系。

## 2. 为什么这仍然有说服力

### 2.1 你手里的不是“玩具数据”，而是论文配套真实机器人记忆树

当前可用数据位于：

- `data/armarx_lt_mem/2024-07-a7a-predef.pkl`
- `data/armarx_lt_mem/2024-07-a7a-summary.pkl`
- `data/armarx_lt_mem/2024-08-27-a7a-predef.pkl`
- `data/armarx_lt_mem/2024-08-27-a7a-summary.pkl`
- `data/armarx_lt_mem/2024-09-18-a7a-predef.pkl`
- `data/armarx_lt_mem/2024-09-18-a7a-summary.pkl`
- `data/armarx_lt_mem/2024-a7a-merged-summary.pkl`
- `data/armarx_lt_mem/qa.json`

这些 `pkl` 不是纯手工摘要文本，而是**真实机器人实验生成后的层级情景记忆树表示**。  
你的遗忘模块恰好就是作用在这类树结构上，而不是必须直接作用在机器人硬盘里的 JPG/WAV。

### 2.2 当前最合适的实验主张

基于现有数据，最合理的主张是：

1. **结构压缩有效**：遗忘后树更轻、更浅、更少细节。
2. **功能退化可控**：在一定遗忘强度下，`S_c`、`S_p` 不会显著崩掉。
3. **策略优于随机**：效用引导遗忘比随机遗忘更能保住关键问答能力。
4. **边界清晰可解释**：对象细节题、邻近关系题更脆弱；高层概述题、跨天总结题更稳。

这四点足以支撑“遗忘模块是有意义的系统组成部分”，并且比空泛讨论更扎实。

## 3. 一个必须写进论文的现实约束

在当前仓库中，`armarx_lt_mem` 的 `pkl` 已经基本不包含原始 `image/sound` 负载；例如在 `2024-a7a-merged-summary.pkl` 中，事件场景的 `raw.image` 与 `raw.sound` 已为 `None`。  
这意味着：

- `Level 1` 的“删除图像/声音”在该数据上**不是完整的真实存储释放复现**；
- 但 `Level 2` 的“摘要保留、删中间结构与关系”仍然是**真实可测的树级压缩**；
- 因此本实验应被表述为：
  - **真实机器人记忆树上的压缩-性能权衡实验**
  - 而不是
  - **真实机器人原始多模态文件删除实验**

建议论文中明确写：

> 由于原论文公开的数据以序列化长期记忆树为主，而非完整原始照片/语音仓库，本文对遗忘模块的验证重点放在记忆树层级表示压缩及其对问答性能的影响，而不将其表述为对真实底层媒体文件管理策略的完整复现。

这样不仅不减分，反而更严谨。

## 4. 研究问题

建议把遗忘模块实验组织成以下 4 个研究问题。

### `RQ1`：遗忘模块能否显著压缩真实机器人长期记忆树？

关注：

- 序列化后文件大小
- 事件节点保留比例
- 场景数保留比例
- 关系数保留比例

### `RQ2`：遗忘后问答能力会退化到什么程度？

关注：

- `S_c`
- `S_p`
- valid answer rate
- 平均 prompt token `T`

### `RQ3`：效用引导遗忘是否优于随机遗忘？

关注：

- 在相近压缩率下，谁的 `S_c / S_p` 更高
- 哪类问题在随机遗忘下退化更严重

### `RQ4`：哪些问题类型最受遗忘影响？

建议至少划分以下问题类型：

- 高层概述类：`Describe what you did.`
- 时间定位类：`What did you do at ...`
- 对象细节类：`What color ...`, `Which object was next to ...`
- 事件统计类：`How often did you ...`
- 失败分析类：`Did you have any problems ...`

## 6. 实验总思路

### 6.1 核心原则

遗忘模块的说服力来自三件事一起出现：

1. **压缩确实发生**
2. **性能下降可控**
3. **优于随机删除**

只做其中一项都不够。

### 6.2 推荐总实验结构

本模块建议分成三组主实验：

1. **压缩效果实验**
2. **问答性能对比实验**
3. **问题类型敏感性实验**

## 7. 对比组设计

为了保证实验干净，建议至少包含以下 4 组。

| 组别 | 配置含义 | 目的 |
| --- | --- | --- |
| `Base` | 不启用遗忘 | 作为主对照 |
| `Random` | 启用随机遗忘 | 作为弱基线 |
| `UBPF` | 启用效用引导遗忘 | 验证核心方法 |
| `UBPF+GraphCentrality` | 启用效用引导遗忘并使用图中心性 | 验证结构重要性是否有帮助 |

说明：

- 当前代码里 `random_mode` 已支持随机遗忘；
- `use_graph_centrality` 已支持结构重要性项；
- 因此这不是概念设计，而是与现有实现直接对齐的实验矩阵。

## 8. 遗忘强度设计

仅比较“开/关遗忘”还不够，建议再做**三档强度**。

| 强度 | `half_life` | `theta_1` | `theta_2` | `min_retain_ratio` | 预期 |
| --- | ---: | ---: | ---: | ---: | --- |
| Mild | `86400` | `0.55` | `0.15` | `0.40` | 轻度压缩，性能最稳 |
| Medium | `21600` | `0.50` | `0.20` | `0.30` | 推荐主结果 |
| Aggressive | `3600` | `0.45` | `0.25` | `0.20` | 压缩更强，检验边界 |

建议：

- 论文主表放 `Medium`
- 附表或消融表补 `Mild / Aggressive`

## 9. 评测指标

## 9.1 功能指标

沿用 H-EMV 论文口径：

- `S_c`：完全正确率
- `S_p`：至少部分正确率（`correct + partial`）
- Valid：有效回答率
- `T`：平均 prompt token（K）

## 9.2 压缩指标

这是遗忘实验必须新增的部分。

建议统计：

- 压缩前后 `pkl` 文件大小
- Event 节点总数
- Scene 总数
- Relation 总数
- `Level 0 / Level 1 / Level 2` 节点数
- Forgetting ratio

如果可以补一点脚本，最好再统计：

- 平均每个事件保留的 scene 数
- 仅摘要保留节点占比

## 9.3 效率指标

可选但推荐：

- 单题平均运行时间
- 平均检索轮数
- 平均展开节点数

如果时间不够，这部分可降级为案例分析。

## 11. 具体实验二：问答性能对比实验

### 11.1 目标

回答 `RQ2` 和 `RQ3`：

- 遗忘是否破坏问答？
- 在相近压缩率下，UBPF 是否优于随机遗忘？

### 11.2 做法

在同一个 `qa.json` 上，对以下组别分别运行问答：

- `Base`
- `Random`
- `UBPF-Medium`
- `UBPF-Medium + GraphCentrality`

推荐先统一使用同一 LLM 配置，例如：

- `armarx_lt_mem/full`
或
- `armarx_lt_mem/full_gemini`

不要混用不同模型做主表，否则遗忘效果会被模型差异掩盖。

### 11.3 核心比较方式

重点不是看“遗忘后是否更高”，而是看：

1. 压缩后 `S_p` 是否仍保持在可接受范围；
2. `UBPF` 是否在同等压缩率下优于 `Random`；
3. `GraphCentrality` 是否能进一步减少退化。

### 11.4 建议表格

| Method | Compression | Valid | `S_c` | `S_p` | `T` |
| --- | ---: | ---: | ---: | ---: | ---: |
| Base | 0 |  |  |  |  |
| Random-Medium |  |  |  |  |  |
| UBPF-Medium |  |  |  |  |  |
| UBPF-Medium + GraphCentrality |  |  |  |  |  |

### 11.5 最有说服力的结果模式

你不需要追求“遗忘后比不遗忘还准”，那很难，也不自然。  
最理想的结果模式是：

- `UBPF-Medium` 比 `Base` 有明显压缩；
- `UBPF-Medium` 的 `S_p` 只小幅下降，甚至接近持平；
- `Random-Medium` 下降更明显；
- `UBPF-Medium + GraphCentrality` 比 `UBPF-Medium` 更稳。

这就已经足够说明你的遗忘不是乱删，而是“有选择地压缩”。

## 12. 具体实验三：问题类型敏感性实验

### 12.1 目标

回答 `RQ4`：遗忘会优先伤害哪类问题。

### 12.2 做法

把 `data/armarx_lt_mem/qa.json` 的 30 个问题人工划分为以下五类：

1. **概述类**
2. **时间定位类**
3. **对象细节类**
4. **事件统计类**
5. **失败/异常分析类**

然后统计每一类在不同遗忘设置下的：

- correct 数
- partial 数
- wrong 数

### 12.3 预期现象

通常应当出现以下趋势：

- **概述类**：最稳，因为本来就依赖高层摘要；
- **事件统计类**：中等稳，因为依赖事件存在性和计数；
- **时间定位类**：对首尾保留和时间索引较敏感；
- **对象细节类**：最脆弱，因为更依赖场景细节与邻接关系；
- **失败分析类**：如果免疫规则保住失败节点，理论上应较稳。

例如：

- `What color was the milk packaging ...`
- `Which object was next to the soy milk ...`

用来诚实说明：

> 当遗忘强度过高时，依赖局部细节的对象级问题会首先退化。

这个负例不是减分项，反而是边界分析。

## 14. 论文中推荐的论证逻辑

你可以按下面这个顺序来写。

### 14.1 先承认数据限制

> 原论文公开的 ARMAR-7 数据以长期记忆树序列化结果为主，未包含完整原始多模态媒体仓库。

### 14.2 再说明为什么仍然可验证

> 由于遗忘模块实际作用对象是层级记忆树中的事件与场景结构，因此我们仍可在该真实机器人记忆树上定量评估遗忘策略对结构规模和问答性能的影响。

### 14.3 然后给出核心结论

> 实验表明，效用引导遗忘在真实机器人长期记忆树上能够以较小的问答性能代价换取明显的记忆压缩，并且在同等压缩强度下优于随机遗忘。

### 14.4 最后给边界

> 遗忘机制更适合保留高层任务摘要、失败经历和对话线索；对于依赖精细场景细节的对象级问题，激进遗忘会带来更明显的性能退化。

这套逻辑是完整且可信的。

## 15. 推荐实际落地顺序

为了降低试错成本，建议按下面顺序推进。

- `Base`
- `Random-Medium`

### Step 3：最后补问题类型分析

对 30 个问题人工标类型并统计分组结果。

这一步最花人工，但对论文质量帮助最大。
