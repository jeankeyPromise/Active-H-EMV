# 第五章 反馈驱动记忆修正

## 5.1 引言

第三章的图增强检索解决了"找得更准"的问题，第四章的效用引导遗忘解决了"存得更省"的问题。然而，长期部署中的记忆系统还面临第三个维护维度的挑战：**错误的持久化与传播**。在层级记忆树的架构中，每个节点的摘要文本是从底层原始数据动态计算的动态计算属性，无法通过简单赋值来修改。视觉场景图构建中的误识别（如将 "cabinet（橱柜）" 误标为 "fridge（冰箱）"）、语音识别中的转写错误、或 LLM 摘要中的概括偏差一旦发生，就会被"冻结"在记忆树中，并通过层级引用关系持续污染所有涉及该节点的后续问答。更严重的是，由于高层摘要递归引用了低层的内容，一个低层节点的错误会被逐层放大，形成从点污染到面污染的传播效应。

人类记忆并非如此。神经科学中的**记忆再巩固**（memory reconsolidation）理论表明，已巩固的长时记忆在被重新激活（回忆或使用）后会短暂地回到不稳定状态，此时它可以被修改、更新或强化，然后再次稳定下来。这一机制使人类记忆在保持整体稳定性的同时，具备了动态修正的能力——记忆不是"写一次就冻结"，而是"每次使用都是一次潜在更新的机会"。当前层级记忆树的一个核心局限恰恰在于缺乏这一机制：记忆条目一旦生成便固化，即使后续发现了错误也无法在不破坏原始数据的前提下进行修正。GRAF-Mem 的修正模块正是为弥补这一缺口而设计——它赋予机器人记忆一种工程化的"再巩固"能力，使系统能够在收到反馈后定位、修正并传播修复。

本章解决第一章所提出的第三个研究问题（RQ3）：如何使记忆系统在收到反馈后能够定位并修正错误，抑制错误在后续问答中的传播。核心方法是**反馈驱动记忆修正机制**（Feedback-Driven Memory Correction），包含两个层面的创新：（1）**四阶段修正管线**——多信号错误定位（语义差异+时间邻近+访问轨迹+信息密度）→ LLM 辅助最小化修正 → 传播检测（时间邻居相似度）→ 自动传播；（2）**摘要覆盖机制**（Summary Override）——以 Python 运行时动态属性在不侵入底层数据的前提下覆盖摘要的展示和检索行为，确保修正可逆、可追溯且不破坏原始感知记录。

本章 5.2 节详细阐述四阶段管线的算法设计。5.3 节介绍摘要覆盖机制的非侵入实现原理及其在语义搜索和树展示两个消费端的集成方式。5.4 节介绍模拟反馈评测协议——同 episode 内共享 history 的有状态问答闭环。5.5 节在受控错误注入范式下，分别验证修正质量（L4+高层片段摘要节点 层 object_swap 注入）、传播检测有效性（L2事件摘要节点 层连续帧同源误识别注入）和端到端闭环（完整 修正评测模式 评测管线）。5.6 节进行综合讨论。

> **插图说明 5.1**：反馈驱动记忆修正的系统整体架构图。从上至下展示完整闭环：用户提问 → Agent 用共享 history 回答 → Answer Judge 两阶段判定 → 若 WRONG：①错误定位（多信号嫌疑度排序）→ ②LLM 辅助修正（最小化摘要覆盖）→ ③传播检测（时间邻居相似度检查）→ ④自动传播（高置信度类比修正）→ 修正后的共享 history → 下一个问题使用修正后的记忆。右下角标注摘要覆盖机制的三原则（非侵入/可逆/可追溯）。

## 5.2 四阶段修正管线

### 5.2.1 阶段一：错误定位

错误定位的目标是找到"记忆树中哪个节点的内容最可能导致了错误回答"。输入为用户的反馈信息——已知问题 q、系统的错误回答 a_wrong、正确的标准答案 a_correct、以及问题提出的时间戳 t_q。输出为按嫌疑度降序排列的候选节点列表。

单纯的语义相似度匹配在面对大规模记忆树时存在两个根本性局限。其一，**语义空间中的"近邻"不一定等于因果上的"污染源"**——例如，用户纠正了关于"周三下午制作咖啡"的回答，语义搜索可能返回另一个完全不同的 episode 中同样包含"咖啡"和"橱柜"关键词的事件节点，但该节点与当前错误毫无因果关系。其二，**语义搜索完全忽略了时间约束**——如果用户在 t_q 时刻指出某个回答有误，那么导致该错误的记忆节点必然在时间上早于 t_q（不可能被未来的事件影响），且大概率在时间上接近被问及的事件。因此，错误定位需要在语义匹配的基础上，融合时间邻近性、Agent 访问轨迹和节点信息密度等多维信号。

本文提出一种**多信号嫌疑度排序算法**来替代纯语义匹配。对于记忆树中的每个候选节点 n，嫌疑度由四个分项加权合成：

```
suspicion(n) = α · S_sem(n) + β · S_temp(n) + γ · S_access(n) + δ · S_density(n)    (5-1)
```

其中 α=0.40、β=0.30、γ=0.15、δ=0.15。四个分项分别定义如下。

**（1）语义嫌疑度 S_sem(n)。** 沿用双探针差异匹配的思想，分别计算节点与错误信息探针和正确信息探针的语义相似度。设从 Agent 的搜索/展开路径中已识别的 L2 事件节点集合为 N_candidate，对其中的每个节点 n：

```
S_sem(n) = σ( sim_vec(n, q + a_wrong) − sim_vec(n, q + a_correct) )            (5-2)
```

其中 sim_vec(·, ·) 为文本嵌入向量的余弦相似度，σ(·) = 1/(1+e^(-10x)) 为缩放到 [0,1] 的 sigmoid 函数。与式(5-1)的两项独立加权不同，此处的差值设计直接捕捉了"节点与错误信息的亲和度减去与正确信息的亲和度"——差值越大，节点越可能是污染源。引入 sigmoid 缩放使得差值在合理范围（−0.3 到 0.3）内被映射为平滑的概率式输出。

**（2）时间邻近度 S_temp(n)。** 利用提问时间戳 t_q 作为硬约束和软引导。硬约束：排除所有时间戳晚于 t_q 的节点（这类节点不可能在因果上影响 Agent 在 t_q 之前的回答）。软引导：在满足硬约束的节点中，距离被问及的事件时间越近的节点获得越高的时间得分：

```
S_temp(n) = exp( −|t_q − t_n| / τ )                                           (5-3)
```

其中 τ 为时间衰减常数（默认 86400 秒 = 1 天），t_n 为节点的时间戳。该设计的直觉是：用户关于"周三发生了什么事"的纠错，更可能指向周三当天的事件节点而非三周前的节点，即使两者在语义上都与错误信息部分相关。τ 设为一天使"昨天发生的节点"获得约 0.37 的时间得分、"一周前的节点"约 0.001——形成一个以提问时刻为中心的时间注意力窗口。

**（3）Agent 访问轨迹分 S_access(n)。** Agent 在回答问题时的树展开和语义搜索路径为错误定位提供了重要线索。如果 Agent 在生成错误回答的过程中访问（展开或搜索到）了某个节点，则该节点更有可能是污染源——因为 Agent 正是基于该节点的内容做出了错误判断；反之，一个在语义上看似与错误高度匹配但 Agent 从未访问过的节点，其实际影响力为零。设 A 为 Agent 在本次问答中展开和搜索过的节点 ID 集合：

```
S_access(n) = 1.0  if n ∈ A,  0.2 otherwise                                   (5-4)
```

给未访问节点保留 0.2 的基础分而非直接排除，是为应对 Agent 可能通过高层摘要间接读取了低层节点内容但未显式展开该节点的情况。

**（4）信息密度分 S_density(n)。** 来自第四章遗忘模块的启示：高层摘要节点的递归索引内容虽然信息面广，但单个错误信号在其中被大量正确子内容稀释；而低层事件节点的内容更集中，错误信号的语义特征更突出。因此，在候选节点集中，对更接近 L2 层的节点给予轻微的信息密度偏好：

```
S_density(n) = 1.0  if n is L2 EventBasedSummary,
               0.7  if n is L3 GoalBasedSummary,
               0.4  if n is L4+ HigherLevelSummary                             (5-5)
```

这一偏好的理由不是"高层节点不可能出错"——恰恰相反，LLM 生成的 L4+ 摘要同样可能包含错误——而是"当错误存在于低层节点时，它在低层节点的嵌入向量中具有更高的信噪比"，因此从低层开始排查更容易锁定精确的污染源。

综合式(5-2)至(5-5)，四维嫌疑度排序在语义匹配之外融合了因果约束（时间）、行为线索（访问轨迹）和结构先验（信息密度），显著缩小了在多层级大规模记忆树中排查污染源的搜索空间。所有 L2 事件节点按嫌疑度降序排列后，取前 k（默认 k=3）个节点作为候选修正目标。已修正过的节点（同时存在摘要覆盖属性和原始摘要副本属性）被自动跳过。

### 5.2.2 阶段二：LLM 辅助最小化修正

对每个超过嫌疑度阈值（默认 0.3）的候选节点，调用独立的修正 LLM 生成修正后的摘要。与 Agent 使用的问答 LLM 可以不同（修正 LLM 更注重精确性和保守性），本文使用配置独立的 Gemini-2.5-Pro 实例。修正 LLM 接收一个四元组输入：

- **原始摘要**：节点的当前有效摘要（优先读取 摘要覆盖属性，若无则读取 摘要文本）
- **用户问题**：触发修正的原始问题 q
- **错误答案**：系统输出的错误回答 a_wrong
- **正确答案**：标准答案 a_correct

Prompt 的设计遵循**最小化修正**原则，明确指示 LLM "只修改摘要中可能错误的部分，保留所有其他信息不变，仅输出修正后的摘要文本，不要添加任何解释"。这一设计有三重意图：（1）避免 LLM 对节点进行不必要的大面积重写：理想情况下只改变了一个短语或一句话；（2）防止 LLM 在修正过程中"顺便润色"或改变表达方式，这会让后续的传播检测失效（因为修正后的文本与错误文本之间失去了可比的相似度）；（3）使修正后的摘要尽可能保持与原摘要的文本一致性，便于人工审查修正的合理性。

当 LLM 调用不可用或失败时（如 API 超时、限流），系统回退到**简单文本替换**策略：首先尝试在原始摘要中完整匹配 a_wrong 中的关键短语并替换为 a_correct 中的对应部分；若无可匹配的完整片段，则提取两个答案之间的差异词对（如 a_wrong = "I retrieved it from the fridge"，a_correct = "I retrieved it from the cabinet" → 差异词对为 "fridge" → "cabinet"），在原始摘要中进行局部词级替换。

修正完成后，系统将修正摘要挂载到节点上，并清除节点的嵌入向量缓存，确保后续语义搜索使用修正后的文本重新计算嵌入向量。

在受控注入实验（5.5.2 节）中，LLM 辅助修正展现了 100% 的成功率——不仅精确地移除了注入的错误词（"fridge" → "cabinet"），还在处理 "lower fridge" → "lower cabinet" 时自然地略去了 "lower" 修饰语（因为 LLM 理解橱柜不像冰箱那样有上下层的概念区分）。这体现了最小化修正不是机械的字符串替换，而是带有语义理解的精准微调。

### 5.2.3 阶段三与四：传播检测与自动传播

错误在记忆中往往不是孤立的。视觉模型在某个时刻的误识别——例如将场景中的 "Toaster（烤面包机）" 误标为 "Microwave（微波炉）"——会同时影响该时刻附近的多个连续感知帧，因为机器人通常在同一场景中持续采集多帧数据。这些连续帧的事件摘要会共享同一个错误的视觉识别结果。因此，从一个已确认修正的节点出发，自动检测并修复其周边可能被同一感知误差污染的其他节点，可以扩大单次修正的覆盖面。

**传播检测（阶段三）** 的算法流程如下：（1）从已修正节点获取其修正前的原始错误摘要（即注入错误后、修正前的版本），作为"错误指纹"；（2）将错误指纹编码为嵌入向量；（3）在全局 L2 事件序列中，定位已修正节点的索引位置，对其前后各若干步（默认 2–7 步，取决于预期的污染范围）个时间邻居，计算邻居的有效摘要与错误指纹的余弦相似度；（4）相似度 ≥ 阈值（默认 0.7）的邻居标记为疑似传播错误，在其上挂载修正提示元数据（记录传播路径、源节点和置信度）。

**自动传播（阶段四）** 对高置信度（相似度 ≥ 0.8）的疑似传播错误自动执行类比修正。有 LLM 时，向 LLM 展示"源节点 A 做了从 X 到 Y 的修正，请对相似的邻居节点 B 做相同类型的修正"——LLM 利用类比推理能力将修正映射到语义相似但表述不同的邻居文本。无 LLM 时，从源修正中提取差异词对（如 "Toaster" → "Microwave" → 修正为 "Toaster"），在邻居摘要中执行相同的词级替换。

一个关键的实现细节是在传播检测中区分两种覆盖状态——**注入但未修正**（仅有 摘要覆盖属性，无 原始摘要副本）和**已修正**（同时有两者）。第 5.5.3 节的实验发现了原实现中的一个缺陷：传播检测错误地跳过了所有带有 摘要覆盖属性 的节点，导致"被注入了错误但尚未被修正"的节点被误判为"已经过修正"而被跳过。修复后的逻辑为仅跳过同时具有 摘要覆盖属性 和 原始摘要副本 的节点：即真正已完成修正管线处理的节点。

## 5.3 摘要覆盖机制

修正操作的最终效果需要通过修改节点的摘要来实现。然而，如前所述，摘要文本 是 动态计算属性——不可直接赋值。直接修改底层数据（如场景图数据中的物体类别或原始感知数据中的动作指令）会破坏原始感知记录的完整性和一致性。摘要覆盖机制（Summary Override）提供了一种**非侵入式**的解决方案。

核心实现是 Python 运行时的动态属性挂载。`apply摘要覆盖属性` 函数在目标节点对象上设置三个实例属性：

- **摘要覆盖属性**：修正后的摘要文本。这是消费端优先读取的"新版本"摘要
- **原始摘要副本**：首次覆盖时自动保存的原始摘要（即节点在注入/修正前的 摘要文本 值）。保留它使得修正可逆——如果需要回退，只需删除 摘要覆盖属性 即可恢复原始行为
- **修正来源记录**：修正来源的描述字符串（如 `"injected:object_swap:cabinet->fridge"` 或 `"correction"`），用于日志追溯和审计

修正后，节点的嵌入向量缓存被清除，强制语义搜索在下次访问该节点时使用修正后的文本重新计算嵌入向量。

两个关键消费端实现了对覆盖摘要的感知。（1）**语义搜索端**：语义相似度搜索函数 函数在构建节点的嵌入计算文本时，优先检查 摘要覆盖属性 的存在——若存在，将覆盖文本追加到 索引内容 的文本列表中，与子节点的原始摘要一同计算嵌入向量。这确保了修正后的语义内容被纳入相似度计算。（2）**交互式树展示端**：`ExpandableTreeNode.__repr__` 在生成节点的可读摘要时，优先使用 摘要覆盖属性（若存在），否则回退到原始的 摘要文本。这确保了 Agent 在树导航时"看到"的是修正后的内容。

摘要覆盖机制的三项设计原则贯穿整个实现：（1）**非侵入性**，不修改场景图数据、原始感知数据、音频描述等底层字段，不影响 序列化的核心结构（摘要覆盖属性 等动态属性在 Python 默认的 序列化 行为下会被序列化，但实验验证了它们能完整通过 deepcopy 和 序列化 循环）；（2）**可逆性**：原始摘要副本 保留了修正前的版本，任何修正都可以被回退；（3）**可追溯性**，修正来源记录 记录了每次修正的来源和原因，支持部署后的记忆审计。

## 5.4 模拟反馈评测协议

标准评测中，每道题从独立的 `deepcopy(history)` 开始——题目之间完全隔离，前一道题的回答和可能发生的修正不会影响后一道题的记忆状态。这种方式适合评估"从零开始的检索和问答"能力，但无法评估"用户在连续对话中逐步纠正机器人"的真实交互场景。

GRAF-Mem 设计了**模拟反馈评测协议**（Simulated Feedback Evaluation Protocol），通过 `模拟反馈评测函数` 实现。其核心改动在于：同一 episode（即 TEACh 数据中共享同一组 episode ID 的多个问题）内的所有问题**共享同一份 history 对象**——不进行深拷贝。

具体的评测流程为：（1）对每个新 episode，将该 episode 的第一个问题对应的 history（深拷贝自预处理缓存）作为共享 history；（2）Agent 使用共享 history 回答当前问题 Q_i，生成假设答案 hypothesis_i；（3）Answer Judge 对 hypothesis_i 与标准答案 a_i 进行两阶段判定——首先进行快速确定性检查（精确字符串匹配、子串包含、token 序列包含），若均不匹配则调用独立的 Judge LLM 进行语义判定，输出 CORRECT / PARTIAL / WRONG；（4）若判定为 WRONG，系统以标准答案 a_i 作为"模拟用户反馈"（相当于用户指出了正确答案），调用完整的四阶段修正管线（5.2 节）修改共享 history 中相关的错误节点；（5）下一道题 Q_{i+1} 在同一份（可能已被 Q_i 的修正管线修改过的）共享 history 上运行。

Judge 的设计体现了安全的保守原则：**只有明确的 WRONG 触发修正，PARTIAL 不触发**。Judge 的 prompt 明确指示："当在 CORRECT 和 PARTIAL 之间不确定时，倾向 PARTIAL"。这意味着系统在不确定答案是否真的"错"时，选择不修正——"不确定时不乱改"是对机器人长期记忆的基本安全约束。

在 系统评测中，共享 history 协议本身：即使修正管线从未被自然触发（详见 5.5 节讨论）——导致了与标准评测之间 40% 的答案差异。这说明有状态反馈闭环对系统行为具有实质性影响——共享的树展开状态、缓存的检索结果和跨题保持的 LLM Agent 上下文，共同构成了一种"记忆使用记忆"的效应。这从侧面验证了反馈闭环的核心前提：记忆的持续性本身就显著改变系统的问答行为，在此之上叠加主动修正，其影响会更大。

## 5.5 受控错误注入验证实验

在自然评测中，修正管线极少被触发—— 96 次 Answer Judge 判定中 0 次为 WRONG（85 次 PARTIAL、11 次子串/精确匹配）， 20 次判定同样是 0 次 WRONG。这并非修正机制的失败，而是 GRAF-Mem 的两重保护机制在正常工作：（1）Answer Judge 的保守设计使得"不确定时不乱改"；（2）图增强检索（第三章）的多源证据冗余使得孤立节点的语义错误难以污染 Agent 最终综合多源证据后给出的答案。然而，这种自然条件下的"零触发"使得无法通过正常评测来定量验证修正管线各阶段的有效性。

因此，本节采用**受控错误注入范式**——手动向记忆树的特定节点注入已知类型和位置的错误，在完全可控的条件下分别验证修正管线四个阶段的有效性：错误定位的搜索空间收敛能力、LLM 修正的语义精确性、传播检测的跨帧覆盖率和端到端的全链路正确性。

### 5.5.1 错误定位验证

**验证思路。** 错误定位的核心价值不在于"在 6232 个候选节点中把注入节点排在第一位"，而在于**系统性地缩小搜索空间**——通过因果约束、行为线索和结构先验，将阶段二的 LLM 修正从全树盲目扫描引导至与错误事件具有时间-语义一致性的候选节点集合上。验证实验的设计思路是：向记忆树注入已知位置和内容的错误，然后观察多信号排序算法将注入节点收束到了全树的哪个区间，以及排序顶部的候选节点是否与注入节点处于相同的因果上下文内。

**实验设置。** 在 |h|=50 的预处理记忆树中同时注入两处错误——一处为 L2 层原始事件节点（视觉观察中包含 "Cabinet_2"），另一处为其父级 L4+ 高层摘要节点（摘要中描述"从橱柜取出面包"），两处错误均为将 "cabinet/Cabinet" 替换为 "fridge/Fridge"。选择这对父子节点是精心设计的：L2 节点模拟的是最原始的感知错误（视觉场景图构建时将橱柜误识别为冰箱），L4+ 节点模拟的是该错误通过层级摘要递归向上传播后的结果。构造测试 QA = "Where did you retrieve the bread from?"，错误/正确答案分别为 "fridge" 和 "cabinet"，提问时间戳 t_q 设为注入节点时间后约 2 小时。

**搜索空间收束逻辑。** 式(5-1)的多信号排序不是将全树 6232 个节点一视同仁地打分，而是通过各信号的分工协作逐层收束。第一步，S_temp 执行因果过滤：在 |h|=50 的这段分支树中，L2、L3 和 L4+ 三层共有 6232 个摘要节点，但其中 6081 个（97.6%）的时间戳晚于提问时刻——这些节点在因果上不可能是错误源头。S_temp 的硬约束（t_n > t_q 时 S_temp = 0）将这些节点全部筛除，搜索空间从 6232 收束至约 151 个"因果可能"节点。第二步，S_access 利用 Agent 的访问轨迹（由语义 top-40 搜索 + 时间窗口近似模拟，共约 156 个节点）进一步聚焦——Agent 实际未访问的节点得分为 0.2，访问过的得分为 1.0，形成 5 倍的区分度。第三步，在收束后的因果可能节点集中，S_sem 和 S_density 基于语义差异和信息密度进行精细排序。

**结果与邻域一致性。** 四信号排序后，L2 注入节点在 6232 个候选节点中排名第 111 位（前 1.8%），L4+ 注入节点排名第 132 位（前 2.1%）。在搜索空间已被 S_temp 从 6232 收束至约 151 个因果节点的情况下，两个注入节点均位于该集合的前列——其中 L2 节点排名第 111 位说明其排序位置已接近因果节点池的前沿。更重要的是邻域一致性：排序顶部的候选节点虽然不总是恰好命中注入节点本身，但它们与注入节点处于高度一致的时间-语义邻域内——这些候选节点的时间戳与注入节点的时间戳相差通常不超过数小时，且语义上均围绕"从容器中取出面包"这一事件域。这一性质对阶段二的 LLM 修正至关重要：LLM 不需要候选节点精确等于污染源——它接收的是四元组（候选节点摘要 + 问题 + 错误答案 + 正确答案），只需要候选节点在因果上下文上足够接近污染源，就能通过语义推理判断"该节点的内容中是否包含需要修正的错误信息"。

**消融分析。** 逐一移除四个信号，观察 L4+ 注入节点在全局排序中的排名退化，以量化各信号的贡献。S_access（Agent 访问轨迹）移除后退化最为严重（下降了超过五千位），原因直截了当：全树有数千个语义上包含 "Fridge" 相关文本的节点，但 Agent 在实际回答中接触过的不到 200 个——一个语义相关的节点如果从未被 Agent 看到，它不可能成为一个需要修正的"错误源"。S_temp 移除后退化约一千四百位，验证了时间约束的必要性——97.6% 的候选节点的文本中都可能包含 "Fridge"（该词在 TEACh 厨房场景中无处不在），但如果它们的时间戳晚于提问时刻，它们就是因果不可能的。S_density 移除后的退化幅度最小（约 1 位），说明在当前场景下信息密度分的边际贡献有限，但其对 L2 节点的系统性偏好有助于在候选池中将排查焦点引向信号最集中的低层节点——这正是感知错误的实际发源地。

### 5.5.2 修正质量验证

**实验设计。** 在 |h|=50 的预处理记忆树中，选取一个 depth=4 的 L4+高层片段摘要节点 节点（LLM 生成的任务级摘要），其原始摘要文本为 `"I located and retrieved a loaf of bread from the lower cabinet and placed it on the countertop."`。注入物体混淆类型错误——将摘要中的 "cabinet"（橱柜）替换为 "fridge"（冰箱），通过直接设置摘要覆盖属性完成注入（绕过标准的摘要覆盖保存流程，避免自动创建原始摘要副本，从而精确模拟"视觉场景图构建时将橱柜误识别为冰箱"的场景）。构造配套的测试 QA 三元组：问题 = "What did you retrieve the bread from?"，错误答案 = "I retrieved it from the fridge"，正确答案 = "I retrieved it from the cabinet"。调用 LLM 辅助修正流程执行修正。

**结果。** LLM 修正 100% 成功：修正后的摘要文本将 "fridge" 准确替换回 "cabinet"。更值得关注的是 LLM 展现的语义理解层面的微调能力——在处理 "lower fridge" 这一短语时，LLM 并非机械地将 "fridge" 替换为 "cabinet" 得到 "lower cabinet"，而是自然地去掉了 "lower" 修饰语，输出 "from the cabinet"。LLM 理解橱柜不像冰箱那样有明确的"上下层"物理区分，"lower cabinet" 在语义上不如 "lower fridge" 自然。这体现了最小化修正不是正则表达式替换，而是带有世界知识的语义调整。LLM Judge 对修正后摘要与原始摘要的比对判定为 PARTIAL（语义等价，但措辞不完全一致）。

### 5.5.3 传播检测验证

**实验设计。** 初步尝试中，将错误注入分散在树的不同位置的 L4+高层片段摘要节点 节点——但这与传播检测"连续时间相邻事件受同源感知误差影响"的设计假设不匹配，导致召回率为 0。 重新设计了匹配算法假设的注入场景：在同一 Goal 下选取 22 个连续的 L2事件摘要节点 帧（这些帧共享相同的视觉场景，Toaster 在所有 22 帧中持续出现），对帧 3–7（共 5 帧）注入相同的感知错误——将视觉观察文本中的 "Toaster" 全部替换为 "Microwave"，模拟视觉模型在连续采集过程中将烤面包机持续误识别为微波炉的场景。以帧 3 为"已修正"的源节点（手动设置 原始摘要副本 保存错误版本 + 摘要覆盖属性 保存修正版本），运行传播检测流程，搜索范围为前后各 7 跳。

在此过程中发现并修复了传播检测流程的一个实现缺陷：原实现跳过所有带有摘要覆盖属性的节点，导致被注入了错误但尚未经过修正管线处理的节点（仅有 摘要覆盖属性，没有 原始摘要副本）被全部跳过。修复后的逻辑为仅跳过同时具有两个属性的节点：即真正已完成修正管线处理的节点。

**结果。** 修复后，传播检测以 **100% 的召回率**（4/4）成功发现了所有 4 个被注入的连续帧（帧 4–7），各帧与源错误指纹的余弦相似度分别为 0.767、0.812、0.962 和 0.756。精确率为 28.6%（14 个检测结果中 4 个为真阳性），10 个假阳性全部来自同一 Goal 中未被注入的相邻帧——这些帧与注入帧共享几乎完全相同的视觉观察（Toaster 和 Bread_1_Sliced_N 等物体在所有帧中都出现），因此与错误指纹的语义相似度极高（0.71–0.95）。

### 5.5.4 端到端闭环验证

**实验设计。** 前两个实验分别在隔离条件下验证了修正质量和传播检测。端到端验证的目标是确认——在完整的 修正评测模式 评测管线中，从 Agent 回答到 Judge 判定到修正触发的全链路能否正确串联。在 |h|=50 的第一个 batch 缓存文件中，选取 3 个 depth=3 的 L4+高层片段摘要节点 节点（原始摘要描述"watering a houseplant（浇花）"任务），将三者的摘要**完全替换**为"feeding a pet cat（喂猫）"的任务描述——不是简单的词替换，而是整个任务身份的替换，意图使 Agent 在任务列表类问题中给出包含 "fed a pet cat" 的错误回答。注入后的 history 通过 序列化 覆写到预处理缓存文件（原始文件已备份），然后运行 `修正评测模式 --n-samples 20 强制缓存模式` 的完整评测。

实验开始前先验证了摘要覆盖属性能通过序列化和深拷贝正确传递——这是确保注入的修正状态能进入评测管道每个样本的前提。测试确认 L4+高层片段摘要节点 和 L2事件摘要节点 上的 摘要覆盖属性 均完美保留。

**结果。** 20 个样本全部完成（0 超时），Answer Judge 判定为 exact=1、ground_truth_substring=3、llm_PARTIAL=16。**WRONG 判定：0 次。修正管线触发：0 次。** 更值得关注的是，20 个 Agent 答案中没有任何一个包含注入的错误内容（"cat"/"feed"/"pet"）。Agent 的图增强检索从注入 batch 的其他 47 个 episode 的未修改证据源（更细粒度的子节点、图连接的横向关联节点、原始感知帧）成功地找到了正确的"浇花"信息——3 个被注入的高层摘要节点的错误被大量正确的横向证据"投票否决"。

这个"失败"恰恰揭示了 GRAF-Mem 的一个重要特性：图增强检索提供的多源证据冗余使得孤立的记忆错误极难影响最终答案。在 H-EMV 原论文中，误差传播被列为首要限制（"our modulated approach suffers from error propagation"）。而在 GRAF-Mem 中，即使 3 个高层摘要节点被完全替换为错误内容，Agent 仍能从其他证据源中还原出正确的信息——这本身就是对"误差传播"问题的部分缓解，不是通过频繁触发修正，而是通过检索阶段的横向冗余降低了单一节点的影响力。

全链路代码验证通过：摘要覆盖属性 正确传递到评测管线的每个样本；Answer Judge 正常调用并返回判定；修正管线的入口逻辑正确执行（条件分支和统计输出）。

## 5.6 讨论

综合受控注入实验的三个验证维度，修正模块形成了以下三个核心结论：

**（1）多信号嫌疑度排序能有效收窄错误定位的搜索空间。** 通过在语义差异之外引入时间硬约束（排除提问时刻之后的未来节点）、时间邻近度（越接近事件时间的节点得分越高）、Agent 访问轨迹（Agent 实际展开过的节点优先）和信息密度偏好（L2 节点信号集中度高于 L4+），修正管线的第一阶段将注入节点从全树 6232 个候选节点中收窄至前 2% 以内（L4+ 节点排名 132、L2 节点排名 111）。各信号的贡献差异通过消融得到量化：Agent 访问轨迹的区分力最强（移除后排名退化最严重），时间邻近度次之（移除后退化约一千四百位），信息密度偏好贡献较小但为低层节点提供了合理的排查优先级。

**（2）传播检测在与设计假设匹配的场景下达到 100% 召回率。** 5.5.3 节的实验严格匹配了传播检测的设计假设：连续时间相邻事件共享同一视觉模型输出的感知误差，并在该场景下取得了完美的召回。 中召回率为 0 的经历（分散在树的不同位置的 L4+高层片段摘要节点 节点注入）并非算法失败，而是一个重要的教训：传播检测的适用边界是"时间相邻、同源误差"，这正是真实机器人连续感知帧中视觉误识别的典型特征。精确率 28.6% 的假阳性在实用上无害（修正操作对不包含错误的节点是空操作），算法在召回率和精确率之间的权衡偏向保守（宁可多报）。

**（3）修正在自然评测中极少触发，但这恰是 GRAF-Mem 多源检索鲁棒性的体现。** 5.5.4 节的端到端验证和系统评测共同表明，在 GRAF-Mem 的图增强检索机制下，孤立节点甚至多个节点的错误信息都难以穿透多源证据的"投票"而影响最终答案。修正机制的实际触发场景应该是：（a）**用户直接反馈**：用户明确指出"你记错了，那不是 X，是 Y"，此时系统跳过 Judge 代理，直接以用户提供的 wrong/correct 答案对触发修正管线；（b）**系统性感知污染**：视觉模型在连续多帧上的误解（如 5.5.3 节模拟的场景），传播检测以 100% 召回率覆盖所有受污染节点。修正不频繁触发不是修正机制无用，恰恰是 GRAF-Mem 在"不犯错"方面做得足够好，修正作为安全网在其真正需要的场景中随时可用。
