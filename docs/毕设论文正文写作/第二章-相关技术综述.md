# 第二章 相关技术综述

## 2.1 引言

随着大语言模型与多模态感知技术的快速发展，服务机器人正逐步从实验室演示走向长期、连续的家庭部署。在这一趋势下，如何让机器人有效组织、检索和维护跨越长时间跨度的经历数据，成为情景记忆研究领域的关键挑战。本章围绕本文提出的 GRAF-Mem 框架所涉及的技术领域，从机器人情景记忆、记忆检索与图增强方法、记忆压缩与遗忘机制、对话系统中的记忆修正四个方面系统回顾已有研究工作，并在每节末尾分析其与本文的联系和差异。接着，本章对 GRAF-Mem 所基于的层级情景记忆框架进行专项介绍，包括层级记忆树的数据结构和交互式记忆访问机制。最后，本章介绍本文实验所使用的主要评测基准和数据集。表 2-1 展示了近年长历史记忆系统的代表性工作概览。

## 2.2 机器人情景记忆

### 2.2.1 基于隐向量的情景记忆方法

早期的机器人情景记忆方法主要基于深度表示学习，将机器人的经历编码为固定维度的潜在向量。这些方法通常使用循环神经网络（RNN）[1]或变分自编码器（VAE）[2]对时序化的感知数据进行压缩编码，在检索时通过向量相似度匹配相关经历。例如，文献[3]提出使用长短期记忆网络（LSTM）将机器人操作序列编码为情景向量，并在后续任务中通过解码器重构相关经历；文献[4]进一步引入注意力机制，使编码器能够选择性关注经历中的关键帧。这类方法的优势在于检索效率高——向量匹配的复杂度与记忆库大小呈亚线性关系——且端到端训练使得编码器和下游任务可以联合优化。

然而，基于隐向量的方法在可解释性和泛化性方面存在显著局限。首先，隐向量的语义不可直接阅读，用户和开发者无法检查"机器人记住了什么"。其次，编码器针对特定任务和场景训练，当机器人遇到训练数据之外的新物体、新动作或新任务时，编码质量会显著下降。再者，固定维度的潜在向量在压缩信息时不可避免地丢失细节——一个 512 维的向量无法完整保留"某天下午三点在厨房水槽旁清洗了一个蓝色陶瓷杯"中涉及的时间、地点、物体属性、动作及状态变化等全部信息维度。

### 2.2.2 基于显式符号存储的情景记忆方法

与隐向量方法相对的是基于显式符号存储的情景记忆方法。这类方法将经历表示为结构化的符号记录——如键值对[5]、关系图谱[6]或一阶逻辑命题[7]——并提供基于规则的检索接口。例如，KnowRob[8]构建了一个基于本体的机器人知识库，通过 SWI-Prolog 推理引擎支持对物体位置、任务状态和事件时序的逻辑查询；RoboEarth[9]则提出了一个云端的机器人经验共享平台，不同机器人可以将自己的经历以结构化语义地图的形式上传和检索。

符号化方法的核心优势在于精确性和可解释性——检索结果是确定性的，推理链可追踪。但其最突出的瓶颈在于**可扩展性**：规则库和本体的构建高度依赖人工设计，当环境中的物体类别从几十扩展到数千、任务类型从预定义扩展到开放域时，手工维护知识体系的工作量呈指数级增长。此外，符号化方法难以处理自然语言中的模糊性和多义性——一个问题可能有多种语义等价的表述方式，而规则式检索无法灵活应对。

### 2.2.3 基于自然语言表示的大模型驱动方法

近年来，大语言模型的涌现能力为机器人情景记忆开辟了第三条路径：将经历直接转化为自然语言文本，利用预训练 LLM 的语义理解和生成能力实现灵活的记忆检索和问答[10]。这种方法兼具隐向量方法的泛化性和符号化方法的可解释性——自然语言文本既能被机器通过嵌入向量进行语义计算，也能被人类直接阅读。代表性工作是层级情景记忆框架（Hierarchical Episodic Memory, H-EMV）[11]，它提出将连续经验流组织为五层树状结构：（1）L0 层为原始多模态感知数据，包括 RGB 图像、深度图、音频流和关节角度序列；（2）L1 层为场景图（Scene Graph），从图像中提取物体列表、属性和空间关系；（3）L2 层为事件摘要（L2事件摘要节点），将单个动作或简短交互片段转化为自然语言描述；（4）L3 层为目标摘要（L3目标摘要节点），概括完成一个子目标的连续事件序列；（5）L4+ 层为高层片段摘要，由 LLM 递归概括直至生成覆盖全部经历的单一根节点摘要。在检索阶段，H-EMV 训练 LLM Agent 以交互式树导航的方式检索证据——Agent 可以沿父子关系展开（expand）节点查看细节、折叠（collapse）无关分支、或使用语义相似度搜索（search）定位相关节点。该方案在 TEACh（模拟家居）、Ego4D（自我中心视频）和 ARMAR-7（真实机器人）三个数据集上验证了可行性，用比完整历史扁平化送入 LLM 低约两个数量级的 token 成本，取得了可比或更优的语义正确率。

然而，H-EMV 及其同类层级记忆方案在**记忆维护**方面仍是空白。具体而言：（1）检索仅依赖树的纵向父子关系和文本相似度，缺乏跨节点的横向语义关联；（2）记忆树是 append-only 的，不具备压缩或遗忘机制；（3）摘要一旦生成便冻结，无法在运行时修正。GRAF-Mem 正是在这一"骨架"之上，引入了事件关联图、效用引导遗忘和反馈驱动修正三层主动维护能力。

> **表 2-1 机器人情景记忆三阶段方法对比**
>
> | 方法类型 | 记忆表示 | 检索方式 | 可解释性 | 泛化性 | 可维护性 |
> |---------|---------|---------|---------|-------|---------|
> | 隐向量方法 | 固定维度潜在向量 | 向量相似度 | 低 | 受限于训练数据 | 无 |
> | 符号存储方法 | 结构化键值/图谱 | 规则推理 | 高 | 受限于手工本体 | 无 |
> | 大模型驱动方法 | 自然语言文本 | LLM Agent 交互式 | 高 | 利用预训练模型 | 弱 |

## 2.3 记忆检索与图增强方法

### 2.3.1 基于向量搜索的记忆检索

基于向量搜索的记忆检索是当前大模型应用中最主流的检索范式，代表性框架包括检索增强生成（Retrieval-Augmented Generation, RAG）[12]。其核心流程为：将文档或记忆条目切分为文本块（chunk），使用嵌入模型（如 Sentence-BERT[13]、OpenAI text-embedding 系列[14]）将各文本块编码为固定维度的稠密向量，构建向量索引（如 FAISS[15]）。在检索时，将用户查询编码为同维度向量，通过最大内积搜索（MIPS）或近似最近邻搜索（ANN）返回与查询最相似的 top-k 个文本块，送入 LLM 生成最终答案。为提升检索精度，近年来出现了多种改进方案：HyDE[16]在检索前使用 LLM 生成假设性答案以缩短查询与文档的语义距离；Multi-Vector Retrieval[17]使用多向量代替单向量表示每个文档，捕获不同语义侧面；Re-ranking[18]在初步检索后使用更强的交叉编码器对候选结果进行精排。

然而，在机器人长期情景记忆场景下，纯文本向量检索面临两个核心挑战：（1）**措辞鸿沟**：同一事件或物体可能以完全不同的措辞被描述，例如用户问"那个蓝色的杯子"，而记忆中的相关事件可能仅描述为"I picked up a mug from the sink"，纯文本相似度无法跨越这种语义等价但在词汇层面不相似的鸿沟；（2）**横向关联缺失**：向量搜索是 item-to-query 的独立匹配，无法利用记忆条目之间的结构化关联，例如"这个杯子后来出现在哪些任务中"需要沿时间线追踪同一物体的跨任务出现记录，而向量搜索返回的是离散的文本块列表，不携带任何块间关系信息。

### 2.3.2 图增强的检索方法

为弥补纯向量检索在结构化关联捕捉上的不足，近年来出现了多种将图结构引入检索流程的方法。知识图谱增强的 RAG（Graph RAG）[19]在检索前利用知识图谱中的实体关系对查询进行扩展：例如从"blue cup"扩展至"mug, cup, vessel, container"等上位词/同义词，以提升召回率；层次化索引方法（如 RAPTOR[20]）将文档组织为聚类树，在不同层级上分别进行向量检索和文本生成，使检索结果既能覆盖宏观主题也能命中微观细节；GraphReader[21]等系统则将长文本显式建模为图结构，以图遍历替代线性阅读进行信息抽取。在视频理解领域，VideoTree[22]和 VideoAgent[23]等工作也采用类似的"结构化索引+LLM Agent 导航"范式，将长视频的帧序列组织为树或图，让 Agent 通过自适应展开定位关键帧。

然而，当前图增强的检索方法有两个共同特征与本课题不同：（1）图结构多用于**离线构建和可视化**，而非直接嵌入在线检索链路：检索仍以向量相似度为主，图仅作为辅助索引；（2）图结构的构建独立于具体的应用需求，图的边类型（实体共现、主题相似度等）是预设的，而非根据具体场景（如机器人事件中的物体、位置、时间等维度）定制的。在机器人情景记忆场景中，事件之间天然存在**时间相邻**（同一目标下的操作序列）、**共享物体**（同一物体出现在多个任务中）、**共位置**（发生在家具/房间等同一空间位置）、**相似动作**（执行了相同或相似的操作）等多维语义关联，这为构建场景化的事件关联图并嵌入检索链路提供了独特机会。更重要的是，在 GRAF-Mem 中，事件图不仅用于增强检索，它的图中心性信号同时服务于遗忘模块的重要性评估，它的图邻居关系同时服务于修正模块的传播检测。这种"一图多用"的设计是本文区别于现有 Graph RAG 工作的核心创新。

## 2.4 记忆压缩与遗忘机制

### 2.4.1 经典遗忘模型在计算系统中的应用

记忆压缩与遗忘在计算系统中有着悠久的研究历史。最早且最具影响力的理论框架是艾宾浩斯遗忘曲线[24]——记忆保持率随时间呈指数衰减：`R = e^(-t/S)`，其中 S 为记忆的相对强度。在信息检索系统中，这一原则被广泛应用于缓存置换策略（如 LRU 及其变体），即最近最少使用的条目优先被淘汰。在数据库和知识库管理领域，时间窗口策略（如滑动窗口、衰减窗口）[25]通过设置固定的保留时长阈值，自动删除超过时限的数据条目。

然而，这些经典策略在面对机器人情景记忆场景时存在明显的不足：（1）时间不是决定记忆价值的唯一因素：三周前的一次失败任务可能比三天前的一次成功例行操作对后续问答更重要；（2）固定时间窗无法区分不同信息类型：图像等大对象应比文本更激进地压缩，但文本中的关键语义信息需要保留；（3）简单的全或无删除缺乏中间状态，在"完整保留"和"彻底删除"之间，存在对低价值记忆进行"高层语义保留但底层细节丢弃"的中间方案。

### 2.4.2 大模型系统中的分层记忆管理

随着 LLM 上下文窗口的不断扩展，如何在有限上下文内有效管理长对话/长文档中的记忆信息成为研究热点。MemGPT[26]提出了一种受操作系统虚拟内存管理启发的分层记忆架构——将 LLM 的上下文视为"主内存"，将外部存储视为"虚拟内存"，通过类似页面置换的机制在对话过程中自动将历史信息在主内存和虚拟内存之间换入换出。MemWalker[27]将长文本组织为摘要树，在问答时让 LLM Agent 从根节点开始逐层导航至相关叶节点。LongMem[28]在 Transformer 解码器之上增加了一个侧边记忆模块，通过注意力机制实现对历史信息的软寻址和选择性遗忘。Recurrent Memory Transformer（RMT）[29]则将固定长度的记忆状态以循环方式在长序列的各个片段之间传递，模拟人类工作记忆的持续更新过程。

这些工作在"如何在有限资源内管理大量信息"这一核心问题上与本文有共同的关注点，但也存在两个关键差异：（1）它们的压缩/管理对象是 LLM 上下文中的文本序列，而本文的管理对象是包含结构化的多模态层级数据（图像、场景图、关系列表等）的记忆树——压缩决策需要感知节点的数据类型和层级位置；（2）它们的记忆管理多服务于单次长对话中的"当前任务"，而非跨越数周到数月的"长期知识"——因此缺少对新近性和重要性的联合评估机制。

### 2.4.3 模型压缩中的渐进式策略

在深度学习模型压缩领域，也涌现出多种渐进式（而非全或无）的压缩策略。结构化剪枝[30]以卷积核或通道为单位进行裁剪，而非零散地剪除单个权重，从而保持网络拓扑的规整性；知识蒸馏[31]通过教师-学生框架将大模型的知识迁移至小模型，实现"精度保留下的参数压缩"。这些技术的共同启示是：压缩不应是二元的保留/删除决策，而应在多个层级上以不同粒度施加不同程度的削减。

本文提出的效用引导渐进式遗忘借鉴了上述"分层级、分粒度压缩"的思想，但将其从神经网络参数的剪枝/蒸馏迁移至记忆树的语义压缩——Level 0 完整保留、Level 1 去细节化（删除图像等大对象但保留全部文本）、Level 2 摘要保留（仅保留高层语义描述）——使得遗忘从"删不删"的二元决策变为"保留多少细节"的连续谱系。

## 2.5 对话系统中的记忆修正

### 2.5.1 基于反馈学习的参数修正方法

对话系统中的错误修正最早和最直接的方法是基于用户反馈进行模型参数更新。在线强化学习[32]将用户的正/负反馈（如点赞、纠错、追问等）作为奖励信号，通过策略梯度方法更新对话策略的参数。在检索式对话系统中，Active Retrieval[33]等工作利用用户反馈信号调整检索查询的生成策略——当用户的后续回复暗示检索结果不够相关时，系统自动修改查询以重新检索。这类方法的优势在于可以通过持续交互不断优化系统表现，但每次修正都需要经过模型推理和参数更新两个阶段，计算成本高，且参数更新可能带来全局性的副作用——修正一个知识点时可能无意中改变了其他知识点的表示。

### 2.5.2 基于知识编辑的条目修正方法

近期，"知识编辑"（Knowledge Editing）[34]成为在不对整个模型进行微调的情况下修改 LLM 中特定事实性知识的研究方向。代表性方法如 ROME[35]和 MEMIT[36]通过对 Transformer 前馈网络中的特定神经元（通常位于 MLP 层的中间层，被认为存储了事实性知识）进行精确的权重修改，实现对特定事实条目的定位和修正。这类方法的优势在于修改的精确性和局部性——理想情况下只改变目标知识而不影响其他知识。但在实际应用中，知识编辑仍面临泛化性不足（修改后的知识未必能在不同的提问方式下稳定输出正确回答）和副作用评估困难（难以穷举被修改神经元所影响的所有知识条目）等挑战。

### 2.5.3 本课题的定位与差异

上述修正方法均在模型参数空间或检索策略空间中操作，而本文面临的是一个不同的问题：在层级记忆树中，错误存在于**记忆数据**本身——某条摘要的措辞偏差、某个场景图中物体的误识别——而非模型的推理能力不足。因此，修正的目标是修改记忆数据条目而非模型参数。此外，记忆树中的错误具有**传播性**：L2 层的错误被 L3 层摘要引用，L3 层的错误被 L4+ 层的递归摘要放大，形成一个以原始错误为源头的污染网络。本文提出的反馈驱动记忆修正机制正是针对这两个特征而设计：（1）**非侵入修正**：通过 Python 运行时动态属性（摘要覆盖属性）覆盖摘要的展示和检索行为，不修改底层原始数据，且保留原始版本支持可逆回退；（2）**传播感知**：从修正后的节点出发，沿时间序列和图邻居检测可能被同一错误污染的其他节点，实现从单点到邻域的修复扩展。

> **表 2-2 对话系统修正方法对比**
>
> | 方法类型 | 修正对象 | 修正粒度 | 可逆性 | 传播感知 | 代表工作 |
> |---------|---------|---------|-------|---------|---------|
> | 参数修正（RL） | 模型参数 | 全局 | 低 | 无 | [32][33] |
> | 知识编辑 | 模型参数/神经元 | 局部 | 中 | 无 | ROME[35], MEMIT[36] |
> | 检索修正 | 检索查询/策略 | 系统级 | 高 | 无 | Active Retrieval[33] |
> | **GRAF-Mem (本文)** | **记忆树摘要节点** | **条目级** | **高** | **有** | 本文 |

## 2.6 层级情景记忆框架

GRAF-Mem 是在层级情景记忆树的骨架上构建的。为了让后续章节的技术阐述有清晰的上下文，本节对层级情景记忆框架的数据结构与交互式记忆访问机制进行专项介绍。

### 2.6.1 层级记忆树的数据结构

层级记忆树将机器人从部署开始的所有经历组织为五层结构，自底向上逐层抽象：

**L0 — 原始感知数据（RawDataInstant）**。L0 层记录机器人在每个时间步的完整感知输入，包括 RGB 图像帧、深度图、音频流、关节角度序列和底层执行器指令。L0 数据是记忆树中最重量的组成部分——一个 episode 中可能包含数千帧 L0 数据，每帧包含约 200KB–2MB 的多模态信息。L0 层提供了后续问答可能需要的全部细节，但也是长期存储开销的主要来源。

**L1 — 场景图（SceneGraphInstant）**。L1 层对每帧图像进行视觉场景理解，提取物体实例列表及其二元关系。每个场景图包含：物体 ID（如 "Mug_0"）、物体类别（如 "Mug"）、物体状态（如 "dirty, filled"）、空间关系（如 "Mug_0 is in/on CounterTop_0"）。场景图为后续的物体检索和空间关系推理提供结构化依据，但其存储也相当可观——平均每个 L2 事件关联数十个 L1 帧，每帧通常包含 20+ 个物体和 30+ 条关系。

**L2 — 事件摘要（L2事件摘要节点）**。L2 层将连续若干帧的原始感知和场景图组织为一个"事件"——通常对应一个具体的操作动作（如 "Pickup(Mug_0)"、"Pour(Sink_Basin)"）或一行用户语音（ASR 识别文本，如 "make coffee"）。L2 层是记忆树中最细粒度的自然语言层，也是事件关联图的节点来源——每个 L2 事件在图中对应一个节点，携带该事件的物体集合、动作标签、位置签名和时间范围。

**L3 — 目标摘要（L3目标摘要节点）**。L3 层将完成一个子目标（Goal）的连续事件序列组织在一起。例如，"制作一杯咖啡"这个 Goal 可能包含"取杯子→倒水→开咖啡机→倒咖啡→端给用户"等 5–15 个 L2 事件。L3 节点带有子目标描述（当前目标），是 Agent 在回答"做了什么事"类问题时的基本检索单元。

**L4+ — 高层片段摘要（L4+高层片段摘要节点）**。L4+ 层由 LLM 递归概括生成：首先将相邻的 Goal 按时间跨度（通常以天为单位）分组为 L4 节点，再将 L4 节点继续向上合并为 L5 节点，以此类推，直到最终生成覆盖整个记忆树的单一根节点摘要。每层的摘要不仅是下层的简单缩写，而是包含跨目标的高层语义关联——例如"制作咖啡"和"清洗杯子"两个相邻 Goal 可能在 L4 层被概括为"早上完成了一系列厨房任务，包括备饮品和器具清洗"。

### 2.6.2 交互式记忆访问机制

层级记忆树的检索不是简单的"给定查询→返回结果"式被动匹配，而是 LLM Agent 在树上的**主动交互式导航**。Agent 工作在 Python 控制台环境中，可以调用一系列预定义的方法与记忆树交互：

- **`history.expand(idx)`**：展开指定子节点，查看其下一层的内容。初始状态下，所有非根节点处于折叠状态，仅显示摘要文本
- **`history.search(query)`**：在当前节点及其子树中进行语义相似度搜索。内部使用嵌入模型将节点的 索引内容（递归定义的索引内容，即该节点及所有子节点的摘要文本拼接）与查询向量比较，返回最相关的子节点
- **`history.collapse_all_but(idx)`**：折叠除指定子节点外的所有其他子节点，保持树的深度在可控范围内
- **`history[2][1].expand()`**：通过索引链（如 `history[2][1]`）直接导航到树的深层节点，然后调用展开查看细节

Agent 的核心决策循环是：收到用户问题 → 在根节点进行语义搜索 → 展开最相关的子节点 → 检查子节点的摘要和子节点列表 → 如果信息已足够则使用 `answer()` 输出最终答案，否则继续在更下层展开或跳转到其他分支搜索。

这种交互式导航范式有三大优势：（1）**token 经济性**：Agent 仅在需要时展开特定节点的细节，而非将整个树扁平化为数十万 tokens 的 prompt——对于 |h|=100 的长历史，未展开的树在 prompt 中仅占约 2000–3000 tokens，远低于完整历史文本的 10 万+ tokens；（2）**可解释性**：Agent 的导航路径（"在根节点搜索'咖啡'→展开第 3 个子节点→在 L4 层找到'下午准备了咖啡和点心'→进一步展开看 L3 细节"）构成了一条自然的解释链，可以呈现给用户；（3）**状态持续性**：Agent 的展开/折叠操作是有状态的——同一 episode 内多个连续问题的检索受益于前序问题的树展开状态。

## 2.7 评测基准与数据集

本文的实验主要依托以下三个数据集/评测基准，覆盖从模拟家居到真实机器人的多样化应用场景。

### 2.7.1 TEACh

TEACh（Task-driven Embodied Agents that Chat）[37]是一个模拟家居环境中机器人执行任务并进行自然语言对话的数据集。它基于 AI2-THOR 模拟器构建，覆盖厨房、客厅、卧室等多种家庭场景。数据集中每条 episode 记录了一个完整的人机交互任务流程：用户通过自然语言指令要求机器人执行特定任务（如"make coffee""clean the plate""put the book on the bed"），机器人执行对应的动作序列（导航、拾取、放置、开关电器等），期间包含用户的反馈性语音（如"the bread is in the lower cabinet""put in the plate"）和系统 ASR 识别结果。

TEACh 是本文最主要的评测平台，使用的长历史问答测试集包含 10 段长历史，每段历史由 5/15/50/100 个 episode 拼接而成（记为 |h|=5/15/50/100）。每段历史配有 10 种不同类型的问答对（共 100 题），涵盖：
- **任务列表型**（sequence_of_task_descs）：列出历史中执行了哪些任务
- **动作描述型**（seq_specific_shortened_low_actions）：描述执行某个特定动作时的步骤
- **时序推理型**（seq_right_after/before_questions）：某任务之前/之后做了什么
- **物体判断型**（seq_simple_object_yes_no）：是否与某个物体交互过
- **日期关联型**（exact_time_to_episode、tasks_to_exact_times、tasks_to_days_ago、days_ago_to_episode）：某任务在什么时间/多少天前执行

评测沿用的指标包括：S_c（Semantic Correctness，完全正确率——回答在语义上完全命中标准答案的比例）、S_p（Semantic Partial，至少部分正确率——回答至少抓住了关键事实的比例）、T（平均 prompt tokens 每 QA）和 Valid Answer Rate（有效回答率，排除超时/格式错误/空回答）。

### 2.7.2 ARMARX_LT_MEM

ARMARX_LT_MEM 收集自德国卡尔斯鲁厄理工学院（KIT）ARMAR-7 人形机器人的真实运行数据。数据覆盖约 3.3 小时的活动，跨越约 2 个月，包含 117 个高细节密度事件。与 TEACh 的模拟环境不同，ARMARX 数据来自真实物理世界——机器人执行的是真实的拾取、放置、导航和交互动作，视觉输入包含真实的光照变化、遮挡和物体杂乱摆放。该数据集为 H-EMV 原论文的评测之一，报告的语义正确率为 43% S_c + 27% S_p。

在本文中，ARMARX 主要用于遗忘模块的机制验证——评估不同遗忘设置下的结构保真度和 relation-rich 事件的保留情况。由于该数据集缺少完整的标准化 QA 评测集（原论文仅含 30 对 QA），本文在遗忘实验中使用结构审计（统计 L0/L1/L2 分布、mean scenes、mean relations）和局部细节切片（仅给模型局部相关 scene graph 的 4 个 relation-sensitive probe）来定量验证。

### 2.7.3 Ego4D

Ego4D[38]是一个大规模自我中心（第一人称视角）视频数据集，由全球多所机构的参与者佩戴头戴式相机在日常活动中录制。本文使用的子集包含约 6:43 小时和 4:28 小时的两段长视频，配有 40 对具有挑战性的 QA 对。由于第一人称视频的视角与机器人传感器回传的视角不完全一致，且动作和物体的标注同样依赖计算机视觉模型，Ego4D 对记忆系统的视觉理解能力提出了更高要求。本文主要将此数据集作为 GRAF-Mem 的跨领域泛化性验证，不将其作为主实验的核心结果支撑。

## 2.8 本章小结

本章从机器人情景记忆的发展脉络出发，回顾了基于隐向量、显式符号存储和自然语言表示的三种记忆表示方法，分析了各阶段方法的优势与局限，并引出了层级情景记忆框架作为本文技术基座的合理性。在此基础上，本章分别对记忆检索与图增强方法、记忆压缩与遗忘机制、对话系统中的记忆修正三个与 GRAF-Mem 核心模块密切相关的技术方向进行了系统综述，在每小节的末尾阐述了现有方法与本文的联系和差异。最后，本章介绍了层级情景记忆框架的数据结构与交互式访问机制，以及本文实验所依托的三个评测基准。

综合本章综述，现有工作在以下方面与本课题存在显著差异，构成了 GRAF-Mem 的研究空间：（1）在记忆检索方面，现有图增强方法多将图作为离线索引，GRAF-Mem 将事件图直接嵌入在线检索链路，且图结构同时服务于遗忘和修正；（2）在记忆压缩方面，现有方法多为全或无删除或固定时间窗切分，GRAF-Mem 采用基于多维效用的三级渐进式软压缩；（3）在记忆修正方面，现有方法多在模型参数或检索策略层面操作，GRAF-Mem 以条目级的、非侵入的、传播感知的方式对记忆数据进行修正。在后续第三章至第五章中，本文将分别对这三个模块的技术实现与实验验证进行详细阐述。
