## 第一章 绪论（约 4500 字）

### 1.1 研究背景

**写什么**（分四层推进）：
1. **人机交互中的记忆问答需求**：服务机器人在长期家庭部署中，需要回答用户关于过去的回溯性问题——"昨天下午你做了什么""那个杯子后来放哪里了""为什么那次任务失败了"。这种能力——将原始经验流转化为自然语言问答——被称为情景记忆语言化（Episodic Memory Verbalization, EMV），是提升人机交互信任感和实用性的关键能力。
2. **从规则到深度学习再到基础模型**：早期方法依赖规则式模板或微调的深度模型（如 Bärmann 2021、DeChant 2023），泛化能力有限。大语言模型（LLM）的出现使得零样本/少样本的语言化成为可能——但直接将完整历史扁平化送入 LLM（one-pass 方案）面临上下文窗口和计算成本的双重挑战：对于数周到数月的机器人运行数据，即使长上下文模型也会遭遇"中间信息丢失"和随上下文长度二次增长的计算开销。
3. **H-EMV 的解决方案**：Bärmann 等（2025）提出层级情景记忆框架（H-EMV），将连续经验流组织为 L0（原始感知）→ L1（场景图）→ L2（事件摘要）→ L3（目标摘要）→ L4+（递归高层摘要）的五层树结构，并训练 LLM Agent 以交互式展开/折叠/搜索的方式在树中导航检索证据。该方案在 TEACh（模拟家居）、Ego4D（人类自我中心视频）和 ARMAR-7（真实机器人）三个数据集上验证了可行性——用比 one-pass 方案低两个数量级的 token 成本，在长历史上取得可比或更优的语义正确率。
4. **本文的继承与拓展**：H-EMV 解决了"长历史如何检索"的纵向扩展问题。GRAF-Mem 在保留其层级树骨架的基础上，进一步解决三个横向/维护维度的问题——这正是 H-EMV 论文在"Conclusion & Discussion"中指出的局限方向（误差传播、缺乏性能保证、缺少更丰富的模态与个性化集成）。

**支撑材料**：H-EMV 论文（arXiv:2409.17702）Introduction；`docs/Key Concept/正确理解h和T.md`

### 1.2 层级情景记忆的三大瓶颈与研究动机

**写什么**：承接 H-EMV 的成就，指出其在长期运行中暴露的三个核心瓶颈——这些瓶颈在 H-EMV 原论文的短时评测中未被充分暴露，但在更长期、更大规模部署中会成为系统性制约：

1. **横向语义关联不足**（检索层）：H-EMV 的检索完全依赖树结构的纵向导航（沿父子层级展开）和节点内文本的语义相似度匹配。但许多回溯性问题本质上依赖跨任务、跨时间的横向联系——如"这个杯子后来出现在哪些任务中""那次失败之前发生了什么"。树结构天然只表达父子包含关系，无法表达这些横向关联。当历史超过数十个 episode 时，纯文本相似度检索容易遗漏关键证据——H-EMV 论文在 Armar-7 的消融实验（仅使用 L3 节点）已暗示了这一点：层级越高，单节点的信息越浓缩但也越容易丢失细节关联。
2. **记忆存储持续膨胀**（存储层）：H-EMV 的记忆树是 append-only 的——新经历不断追加为新节点，但旧节点从不被压缩或移除。对于跨越数月的真实部署，pickle 序列化文件和底层树结构将随 episode 数量线性增长。H-EMV 论文本身未涉及存储管理——其评测中 |h| 最大为 100 个 episode，在该规模下存储尚可接受，但论文结论部分已指出"长期部署"的挑战。
3. **错误写入后的持久化污染**（维护层）：H-EMV 的摘要（`nl_summary`）从底层原始数据动态计算生成——视觉感知（场景图构建）、LLM 摘要等任一环节的偏差一旦写入，便成为冻结的错误。更严重的是，由于 Agent 在多个问题中共享同一份记忆树，一个节点的错误会污染所有涉及该节点的后续问答。H-EMV 论文在讨论部分明确将"误差传播"列为首要限制（"our modulated approach suffers from error propagation"）。

**支撑材料**：H-EMV 论文 Section V (Conclusion & Discussion)；`docs/Key Concept/图检索核心思想.md`、`docs/Key Concept/遗忘模块总结.md`、`docs/Key Concept/修正模块.md`

### 1.3 研究目的与研究内容

**写什么**：在 H-EMV 层级记忆树之上构建 **GRAF-Mem**（Graph-Retrieval and Adaptive Forgetting Memory），引入三类主动维护能力——这三个模块共享同一个事件关联图数据结构，分别利用它来完成检索扩展、遗忘指导和传播检测：

- **（1）事件关联图与图增强检索**（对应第三章）：从 L2 事件节点自动派生包含时间、物体、位置、动作、因果五类边的关联图，将横向语义联想嵌入检索链路。在语义种子召回后执行图邻居扩展与联合重排，弥补纯树结构文本搜索的不足。
- **（2）基于效用的渐进式遗忘**（对应第四章）：综合新近性（艾宾浩斯曲线）、独特性（语义距离）、重要性（对话/失败/图中心性）三个维度对每个事件节点打分，执行 Level 0（完整保留）/ Level 1（去细节化）/ Level 2（摘要保留）三级渐进压缩——不是一刀切删除，而是在不同层级上施加程度不等的信息削减。
- **（3）反馈驱动记忆修正**（对应第五章）：通过"错误定位→ LLM 辅助修正→传播检测→自动传播"四阶段管线，以非侵入的摘要覆盖机制（`_summary_override`）实现可逆、可追溯的运行时记忆修正。配套的模拟反馈评测协议使同 episode 的多道题共享修正后的记忆状态。

**支撑材料**：`docs/论文写作准备/GRAF-Mem_研究内容与实验结果整理_最终版.docx` 第 1.2–1.3 节

## 第二章 相关工作（约 5000 字）

### 2.1 机器人情景记忆

**写什么**：回顾情景记忆在机器人领域的三个发展阶段——（a）基于隐向量的深度模型（将经历编码为固定维度的潜在表示，检索效率高但可解释性差）；（b）基于显式存储的符号化方法（以结构化的键值/图形式存储经历，可解释但难以扩展）；（c）基于文本表示的大模型驱动方法（将经历转化为自然语言摘要，兼具可解释性和泛化能力）。重点介绍 H-EMV 的五层树结构设计和 LLM Agent 交互式检索范式，以此作为 GRAF-Mem 的技术基座。

**支撑材料**：H-EMV 论文 Section II-A (Episodic Memory for Robots)；`README.md`；`em/em_tree.py`

### 2.2 机器人经验语言化

**写什么**：回顾机器人经验语言化的技术演进——从早期规则式方法（Rosenthal 2016 的模板问答、Zhu 2017 的脚本式总结），到基于微调深度模型的方法（Bärmann 2021 的端到端视觉-语言模型、DeChant 2023 的 TEACh 数据集与序列到序列模型），再到 H-EMV 等利用预训练大模型的零样本/少样本方法。GRAF-Mem 延续了 H-EMV 的"使用预训练模型+结构化记忆"路线，但将关注点从"如何在长历史上高效检索"推进到"如何在长历史上持续维护记忆"。

**支撑材料**：H-EMV 论文 Section II-B (Robot Experience Verbalization)

### 2.3 记忆检索中的图增强方法

**写什么**：回顾图结构在知识检索中的应用——从知识图谱增强的 RAG（Graph RAG）到视频理解中的场景图。H-EMV 和 GRAF-Mem 与 VideoTree、VideoAgent、MoReVQA 等"LLM-as-agent + 结构化索引"的同期工作共享了"不依赖训练、用代码执行驱动 LLM 导航"的理念，但 GRAF-Mem 的独特之处在于（a）记忆树和事件图的构建独立于用户查询（query-agnostic），（b）图不仅用于检索还同时服务于遗忘和修正。

**支撑材料**：H-EMV 论文 Section II-C (Video Understanding / VideoQA)；`docs/Key Concept/图检索核心思想.md`；`docs/Key Concept/GRAPH_ADVANTAGES_EXAMPLES.md`

### 2.4 记忆压缩与遗忘机制

**写什么**：回顾经典记忆遗忘模型（艾宾浩斯遗忘曲线）在计算系统中的应用，以及已有的记忆压缩/蒸馏方法（如 KiS 的关键信息保留、MemGPT 的分层记忆管理等）。指出现有方法多为全或无删除或固定时间窗切分，缺少"渐进式软压缩"——在不同层级上施加不同程度的信息削减，用连续效用分数替代离散的保留/删除决策。

**支撑材料**：`docs/Key Concept/遗忘模块.md`、`docs/Key Concept/遗忘模块总结.md`、`docs/Key Concept/遗忘模块如何完整重构.md`、`docs/Key Concept/one-pass与树结构遗忘的关系.md`

### 2.5 对话系统中的反馈学习与记忆修正

**写什么**：回顾对话系统中的反馈学习与纠错机制——从在线强化学习（通过用户反馈更新模型参数）到检索式修正（通过外部知识库验证和替换错误事实）。指出现有方法多在训练阶段进行全局参数更新，而非在运行时对特定记忆条目进行精确的、最小化的、可逆的修正。GRAF-Mem 的摘要覆盖机制实现了"非侵入式运行时修正"——不改底层数据，不触发重训练，不破坏原始感知记录。

## 第三章 GRAF-Mem：图增强检索与结构化问答（约 7000 字）

### 3.1 引言

**写什么**：本章解决 RQ1（横向语义关联不足）和 RQ2（长历史问答稳定性与 token 成本控制）。H-EMV 的检索范式是纯纵向的：Agent 沿树的层级路径展开/搜索节点，证据召回的上限由树的层级结构和文本语义相似度决定。本章提出的图增强检索在不修改树存储结构的前提下，在树之上插入一层图索引——事件节点之间的关系边提供了横向联想路径，使检索从"沿树上下搜索"升级为"沿图横向扩展"。

**支撑材料**：H-EMV 论文 Section III-B (EM Access)；`llm_emv/memory_graph.py`；Phase 23、24 实验结果

### 3.2 事件关联图构建

#### 3.2.1 图节点与边类型设计

**写什么**：从 EventBasedSummary（L2）自动派生图节点——每个 L2 事件对应一个图节点，继承其物体集合、动作标签、位置签名和时间范围。五种边类型分别编码不同的横向关系：（a）TEMPORAL_ADJACENT——同一目标下前后相邻的事件（零成本规则）；（b）CO_OBJECT——共享物体实例 ID 的事件（零成本规则，加权为 Jaccard 系数）；（c）CO_LOCATION——共享位置签名的事件（零成本规则，用大型固定物体如家具作为位置代理）；（d）SIMILAR_ACTION——动作类型语义相似的事件（低成本嵌入计算，只计算 M 个唯一动作对的相似度而非 N² 个节点对）；（e）CAUSAL——LLM 推断的因果关联（可选中成本）。每种边类型都有密度控制策略——max_group_size 过滤过于常见的物体、max_edges_per_node 限制单节点最大边数、候选边按权重降序选择。

**支撑材料**：`llm_emv/memory_graph.py` 中 `EdgeType`、`GraphNode`、`build_memory_graph` 及各 `_build_*_edges` 函数

#### 3.2.2 图构建流程与缓存

**写什么**：图从树自动派生，不需要额外的人工标注或训练。通过历史结构签名（`_history_structural_cache_key`——基于节点类型、时间范围和摘要内容的确定性哈希）实现图缓存，评测中同一 history 的多次调用共享同一图结构。图构建在记忆巩固（遗忘）之后执行——遗忘先压缩树中的冗余节点，图在精简后的节点集上构建，形成"先筛后连"的管线。

**支撑材料**：`llm_emv/setup.py` 中 `create_memory_graph_cached`、`_history_structural_cache_key` 函数

### 3.3 图增强检索

#### 3.3.1 语义种子召回

**写什么**：使用 all-mpnet-base-v2（768 维）嵌入模型对交互式树节点进行语义搜索。`history_search_similarity` 计算节点 index_content 与查询的最大余弦相似度——设计为 max-pooling 而非 mean-pooling，使"节点中哪怕只有一句话与用户查询高度相关"也能被召回。FAISS flat 索引加速大规模检索。

**支撑材料**：`llm_emv/emv_api.py` 中 `history_search_similarity` 函数；`llm_emv/faiss_search.py`

#### 3.3.2 图邻居扩展与联合重排

**写什么**：三阶段检索流水线——（1）语义种子召回：从交互式树中选出 top-k 语义候选节点 S₀；（2）图邻居扩展：对 S₀ 中每个节点，沿图边扩展到其邻居，形成扩展集 S₁。扩展过程支持问题意图感知的边类型选择——时间类问题激活 TEMPORAL_ADJACENT，对象类问题激活 CO_OBJECT，位置类问题激活 CO_LOCATION；（3）联合重排：`score(q, n) = α·sim_vec(q, n) + β·Σ(w(e)·sim(q, neighbor)) + γ·depth_bonus(n)`。α=0.7 确保语义相关性始终占主导，β=0.25 引入图结构信号，γ=0.05 微调层级偏好。

**支撑材料**：`llm_emv/graph_augmented_search.py`；`docs/Key Concept/图检索如何提升系统性能.md`

### 3.4 结构化检索工具与执行护栏

#### 3.4.1 工具列表与设计动机

**写什么**：H-EMV 的 Agent 通过通用的 expand/search 与树交互，但在长历史上容易陷入盲目展开或重复搜索。本章将层级记忆树中的结构性信息显式暴露为可调用工具——task_list（按时间序列列出任务级摘要）、task_lookup（用查询匹配任务描述）、object_lookup（按物体名检索出现过的任务）、date_lookup（按精确日期/相对天数检索）、event_date_lookup（按事件描述检索发生日期）、temporal_neighbor（给定目标任务，查其前后相邻任务）、action_lookup（底层动作到高层任务的映射）。这些工具将"在几十万字符历史中自由推理"转变为"沿结构化路径定位证据"，是 |h|=50/100 评测中 token 成本和稳定性控制的关键。

**支撑材料**：`llm_emv/emv_api.py` 中 `EMVerbalizationAPI` 类的各 `@group('util')` 方法；Phase 9、10、11 记录

#### 3.4.2 缓存、checkpoint 与执行护栏

**写什么**：（a）multi-history cache 预构建——评测前批量调用 LLM summarizer 为所有选中 episode 生成层级摘要缓存，评测中仅读取缓存；（b）cache audit / require-cache——运行前审计覆盖率，正式运行禁止在线摘要调用以防止隐藏成本；（c）checkpoint / resume / retry——支持长运行中断恢复和瞬时 API 错误重试；（d）prompt token 护栏——单样本和平均 prompt token 上限防止异常样本破坏实验；（e）短对象护栏——对 "cd" 等超短对象名限制过宽匹配，防止漂移到无关证据。

**支撑材料**：`llm_emv/eval/dechant_qa_dataset.py` 中缓存逻辑；Phase 14、17、19、23 记录中关于缓存和护栏的改进

### 3.5 TEACh 长历史问答实验

#### 3.5.1 实验设置

**写什么**：TEACh 测试集（10 段长历史 × 10 种问题类型 = 100 QA），|h|=50（约 1–2 个月的模拟机器人活动）和 |h|=100（约 2–3 个月）两种设置。基线为原始 H-EMV 论文报告的 full multimodal ICL=1 结果。评测沿用 H-EMV 的指标（S_c、S_p）并补充 Wrong/no-answer 率和 T（prompt tokens/QA）。Agent 使用 Gemini-2.5-Pro，H-EMV 基线使用 GPT-4（原文设置）。

#### 3.5.2 主实验结果

#### 3.5.3 结果分析与机制归因

**写什么**：H-EMV 论文的核心主张是"用层级检索替代 flatten 可以大幅降低 token 成本"。GRAF-Mem 的结果不仅验证了这一主张（token 降低 78–80%），还在语义正确性上取得了实质性提升（+11 到 +15 个百分点）。这种提升的来源不是单一因素，而是三者的协同：

1. **事件图扩展了检索覆盖面**——纯文本相似度搜索在 |h|=100 时遗漏的相关证据，通过共享物体边和时间相邻边被纳入候选池
2. **结构化工具降低了搜索噪声**——Agent 不再在几十万字符历史中盲目展开/搜索，而是通过 task_lookup、event_date_lookup 等工具精确命中目标
3. **缓存与护栏消除了隐藏成本**——H-EMV 基线中的 prompt token 数（10.2K–10.4K）包含大量未缓存的原始帧展开和在线摘要调用；GRAF-Mem 通过预处理缓存和 require-cache 机制将这部分成本完全剥离

特别值得注意的是，在 |h| 从 50 翻倍到 100 时，GRAF-Mem 的 S_c 从 48.0% 变为 49.0%（基本持平），而 H-EMV 从 37.0% 降到 34.0%（下降 3pp）。这说明图增强检索在一定程度上抵消了历史增长带来的检索难度。

## 第四章 效用引导的渐进式遗忘（约 7000 字）

### 4.1 引言

**写什么**：本章解决 RQ3（长期运行中记忆存储持续膨胀）。H-EMV 的记忆树是 append-only 的，论文中 |h| 最大为 100，在该规模下 88.8 MB 的 pickle 文件尚可接受。但如果机器人持续运行数月甚至数年，event 数、scene 数、relation 数和 pickle 文件大小将线性增长——这不仅是存储问题，过大的记忆树也会拖慢图构建和检索速度。遗忘模块的核心目标不是提高 QA 准确率（不应期望"忘了冗余信息反而答得更准"），而是在保持问答能力基本稳定的前提下控制长期存储开销。本章的核心理念是**渐进式软压缩**——不同于 H-EMV 论文中讨论的硬删除，而是在三个层级上施加程度不等的信息削减。

**支撑材料**：H-EMV 论文 Section V (Discussion)；`docs/Key Concept/遗忘模块.md`；`docs/论文写作准备/遗忘模块的实验设计说明.md`

### 4.2 效用函数设计

#### 4.2.1 新近性（Recency）

**写什么**：基于艾宾浩斯遗忘曲线的指数衰减：`R(t) = e^(-λt)`，`λ = ln(2) / half_life`（默认 half_life = 3600s = 1 小时）。在 TEACh 评测中，以 question_time 作为 now_time——模拟"在提问时刻回忆过去"的场景。该设计的直觉是：距离提问时刻越近的事件越可能被追问或复用，因此近期事件享有更高的保留权重。

**支撑材料**：`llm_emv/memory_consolidation.py` 中 `compute_recency` 函数

#### 4.2.2 独特性（Uniqueness）

**写什么**：`Uniqueness(n) = 1 - mean(cos_sim(n, siblings))`。在兄弟节点（同一 Goal 下的其他 EventBasedSummary）中语义越独特的事件效用越高；高度重复的日常动作（如反复 Forward/TurnLeft 导航帧）效用低，更容易被压缩。与开题报告中设想的"增量聚类合并"方案不同，这里用连续独特性分数替代离散的"重复/不重复"二分法——不需要判断"这两个事件是否重复"，只需要知道"这个事件和周围事件有多不同"。这避免了合并操作对树结构的侵入式修改。

**支撑材料**：`docs/Key Concept/遗忘模块如何完整重构.md` 第一部分的分析；`llm_emv/memory_consolidation.py` 中 `compute_uniqueness` 函数

#### 4.2.3 重要性（Importance）与图中心性

**写什么**：重要性综合四个独立信号——（a）包含用户对话（ASR 识别文本）→ +0.35，因为用户语音交互是回答"当时发生了什么"的核心线索；（b）动作状态异常（失败/中断）→ +0.20，因为失败经历对诊断性问答（"为什么那次没成功"）至关重要；（c）目标状态变化 → +0.10，标记任务的起止边界；（d）图度中心性 → 归一化映射到 [0, 0.35]，在记忆图中连接的边越多、作为"结构枢纽"的事件越重要。这是图结构"一图两用"的第一处交叉——第三章用它做检索扩展，本章用它做遗忘保护。

**支撑材料**：`llm_emv/memory_consolidation.py` 中 `compute_importance`、`_build_temp_graph_for_centrality` 函数

### 4.3 渐进式遗忘策略

#### 4.3.1 三级遗忘操作

**写什么**：详细介绍 Level 0/1/2 的操作与适用场景。

| 等级 | 条件 | 操作 | 典型空间节省 | 对问答的影响 |
|------|------|------|------------|------------|
| Level 0 | U ≥ θ₁ | 完整保留所有层级数据 | 0% | 支持全部问答类型 |
| Level 1 | θ₂ ≤ U < θ₁ | 删除 L0 原始感知数据（图像、声音等大对象），保留 L1–L4 的文本表示 | 约 80%（单节点） | 纯文本问答正常；VQA（看图回答）功能丧失 |
| Level 2 | U < θ₂ | 压缩为摘要保留：清空 scenes、relations、objects、audio_description 等，仅保留 nl_summary 文本和 range 时间戳 | 约 95%（单节点） | 仅支持 overview/时间线/任务结果类问题；对象邻接、精确位置、局部 relation 类问题退化 |

**支撑材料**：`llm_emv/memory_consolidation.py` 中 `apply_forgetting_level_1`、`apply_forgetting_level_2` 函数；`docs/论文写作准备/遗忘模块的实验设计说明.md`

#### 4.3.2 遗忘豁免与安全机制

**写什么**：四重保护确保遗忘不会误伤关键证据——（a）包含用户对话的节点永不遗忘；（b）目标状态为失败的节点永不遗忘；（c）每个 Goal 的首尾事件受保护（不低于 Level 1），确保目标的开始和结束不丢失；（d）`min_retain_ratio`（默认 0.3）安全下限，当实际 Level 0 保留比例低于阈值时自动下调 θ₁ 和 θ₂ 直到满足。

#### 4.3.3 遗忘在图构建之前执行

**写什么**：遗忘 → 图构建的"先筛后连"管线。遗忘压缩低效用节点，图在精简后的节点集上构建——图更小、边更稀疏、检索更聚焦于高价值证据。两个模块共享同一个图结构但从中提取不同的信号：第三章的图增强检索利用图边做邻居扩展（"哪些节点应该被看到"），本章的遗忘利用图中心性做重要性评分（"哪些节点不应该被遗忘"）。

## 第五章 反馈驱动记忆修正（约 5000 字）

### 5.1 引言

**写什么**：本章解决 RQ4（记忆错误持久化与传播）。H-EMV 论文在讨论部分将"误差传播"列为首要限制："our modulated approach suffers from error propagation, where inaccuracies in early processing steps can compound through the hierarchical structure"。在层级树中，nl_summary 是从底层 raw/scenes 动态计算的 @property，无法直接赋值修改——这是 H-EMV"一旦写入便冻结"的技术根源。本章提出的摘要覆盖机制（Summary Override）以 Python 运行时动态属性的方式绕过这一限制：不修改底层数据，而是在消费端（语义搜索、树展示）优先读取覆盖版本。

**支撑材料**：H-EMV 论文 Section V；`docs/Key Concept/修正模块.md`；`docs/论文写作准备/反馈修正模块论文级详解.md`

### 5.2 四阶段修正管线

#### 5.2.1 阶段一：错误定位

**写什么**：给定用户的反馈（问题 q、错误回答 a_wrong、正确回答 a_correct），构造两个探针查询并计算嫌疑度：`suspicion(n) = 0.6·sim(n, q+a_wrong) + 0.4·(1 - sim(n, q+a_correct))`。设计直觉：高第一项表示节点内容与"错误信息"语义相关，高第二项表示与"正确信息"语义不相关——两者兼具的节点最可能是污染源。权重 0.6:0.4 略偏向第一项，因为大多数情况下"包含错误信息"的信号比"不包含正确信息"更可靠（后者可能只是节点讨论的是不同任务）。已修正过的节点自动跳过。

**支撑材料**：`llm_emv/memory_correction.py` 中 `localize_error` 函数；Phase 40 关于定位精度的分析

#### 5.2.2 阶段二：LLM 辅助单点修正

**写什么**：对超过嫌疑度阈值的候选节点，使用独立的修正 LLM（可与 Agent 不同的模型配置）生成修正后的摘要。LLM 接收四个输入——原始摘要、问题、错误答案、正确答案——Prompt 明确指示"只修改可能错误的部分，保留所有其他信息，只输出修正后的摘要文本"。这种**最小化修正**策略避免了过度重写——不是重新概括整个节点，而是精准定位并修正被污染的信息片段。当 LLM 不可用时回退到差异词替换。

**支撑材料**：`llm_emv/memory_correction.py` 中 `correct_node_with_llm`、`_simple_text_correction` 函数

#### 5.2.3 阶段三与四：传播检测与自动传播

**写什么**：从已修正节点出发，沿时间序列（全局 EventBasedSummary 扁平列表）检查前后各 max_hops 个邻居。对每个邻居计算其有效摘要与源节点修正前错误摘要的余弦相似度——≥ 0.7 标记为疑似传播（`_correction_hint`），≥ 0.8 自动执行类比修正。设计假设：视觉模型在某个时刻的误识别（如把 Toaster 看成 Microwave）会同时污染多个连续感知帧——因为这些帧共享同一场景、同一视觉模型输出。

**支撑材料**：`llm_emv/memory_correction.py` 中 `detect_error_propagation`、`auto_propagate_correction` 函数

### 5.3 摘要覆盖机制与消费端集成

**写什么**：`_summary_override` 的设计决策——（a）非侵入：不修改 scenes/raw 等底层数据，不影响 pickle 序列化核心结构；（b）可逆：`_original_summary` 保留原始版本，支持回退；（c）可追溯：`_correction_source` 记录修正原因和来源。两个消费端的适配——语义搜索端 `history_search_similarity` 在计算节点嵌入时将覆盖文本纳入 `index_content`；展示端 `ExpandableTreeNode.__repr__` 优先使用覆盖摘要。

**支撑材料**：`llm_emv/emv_api.py` 中覆盖检查逻辑；`llm_emv/interactive_tree.py` 中 `__repr__` 修改；`docs/论文写作准备/反馈修正模块论文级详解.md` 第 2.1 节

### 5.4 模拟反馈评测协议

**写什么**：标准评测给每道题独立的 deepcopy(history)，模拟"每题从零开始"的场景。修正评测相反——同一 episode 内的所有问题共享同一份 history 对象，模拟"用户在连续对话中逐步纠正机器人"的场景。评测流程：Agent 用共享 history 回答 Q_i → Answer Judge 两阶段判定（快速确定性匹配 → LLM 语义判断）→ 若 WRONG，以 ground truth 作为模拟用户反馈触发修正 → Q_{i+1} 用修正后的 history 回答。Judge 设计为保守：只有明确的 WRONG 触发修正，PARTIAL 不触发——这是对机器人记忆系统的安全保护："不确定时不乱改"。

**支撑材料**：`llm_emv/eval/qa_eval.py` 中 `run_evaluation_with_correction`、`is_answer_correct`；Phase 38–39 记录

### 5.5 受控错误注入验证

**写什么**（总起）：由于 Answer Judge 在自然评测中的保守性（Phase 38 中 96 次判定 0 次 WRONG）+ GRAF-Mem 多源检索的鲁棒性，修正在自然问答中极少被触发。本章采用受控错误注入范式——手动向记忆树注入已知错误，在完全可控的条件下定量验证修正管线四个阶段的有效性。

#### 5.5.1 修正质量验证

**写什么**：向 HigherLevelSummary（depth=4）节点注入 object_swap 错误——将 "cabinet"（橱柜）替换为 "fridge"（冰箱）。调用 correct_node_with_llm，LLM 接收原始摘要+问题+错误答案+正确答案。修正 100% 成功——LLM 不仅移除了错误词 "fridge"，还在修正 "lower fridge" 为 "lower cabinet" 时自然地去掉了 "lower"（因为 LLM 理解"橱柜没有冰箱那样的上下层"）。这体现了最小化修正不是机械的字符串替换，而是语义理解后的精准调整。

**支撑材料**：Phase 40 记录

#### 5.5.2 传播检测验证

**写什么**：构造符合传播检测设计假设的注入场景——同一 Goal 下的 22 个连续 EventBasedSummary 帧（Toaster 在所有帧中持续出现），向帧 3–7 注入 Toaster→Microwave 的视觉误识别。修复了 detect_error_propagation 中的一个实现缺陷——原代码错误跳过所有带 `_summary_override` 的节点，修复后仅跳过同时具有 `_original_summary` 的节点（即真正已经过修正管线处理的节点）。

#### 5.5.3 端到端闭环验证

**写什么**：将任务身份替换错误（"浇花" → "喂猫"，3 个 depth=3 的 HigherLevelSummary 节点）注入 |h|=50 缓存 pickle 文件，运行完整 `--enable-correction`（n=20）。验证了 `_summary_override` 通过 deepcopy 和 pickle 序列化正确传递到评测管线的每道题。结果：20 题 0 次 WRONG、0 次修正触发——Agent 的图增强检索从其他 47 个 episode 的未修改证据源找到了正确的"浇花"信息，完全绕过了 3 个被注入的高层节点。

这个"失败"恰好揭示了 GRAF-Mem 的一个重要特性：多源证据交叉验证使孤立错误极难污染最终答案。H-EMV 论文指出的"误差传播"风险在 GRAF-Mem 中得到了部分缓解——不是因为修正机制频繁触发，而是因为图增强检索的横向证据冗余降低了任何单一节点错误的影响力。

**支撑材料**：Phase 42 记录

### 5.6 讨论

**写什么**：修正机制的三个定位层次——（1）**交互式修正接口**：当用户直接指出错误时（"你记错了，那天不是浇花，是喂猫"），系统可以通过定位+修正精准修复，Phase 40 已验证此场景下修正 100% 成功；（2）**系统性污染的安全网**：当感知错误不是孤立节点而是跨多帧的系统性误识别时（如连续 5 帧的 Toaster→Microwave），传播检测以 100% 召回率覆盖所有污染节点，Phase 41 已验证；（3）**修正不频繁触发恰是系统鲁棒性的证明**：H-EMV 论文担心的"误差传播"在 GRAF-Mem 中因图增强检索的多源冗余而被部分抑制——这不是修正机制的失败，正是检索机制的成功。

**支撑材料**：Phase 40–42 综合分析；`docs/论文写作准备/反馈修正模块论文级详解.md`

### 6.1 工作总结

**写什么**：回顾 H-EMV 的三个瓶颈与 GRAF-Mem 的三个模块的对应关系。逐条总结核心实验结论——（1）图增强检索：|h|=100 下 S_c=49.0%, S_p=75.0%, T=2.29K，相对 H-EMV baseline 提升 15pp S_c 且 token 成本降低 78%；（2）效用引导遗忘：Forget+Graph 以 5.26% pickle 压缩保持 100/100 答案一致，Level 2 强压缩以 31.70% pickle 压缩和 50.83% relation 压缩保持 100/100 答案一致；ARMARX 结构审计和局部切片证明图中心性使遗忘从"删多少"升级为"优先忘低价值节点"（medium_graph 4/4 vs medium 0/4）；（3）反馈驱动修正：LLM 修正质量 100%，传播检测召回率 100%，端到端全链路代码验证通过。强调三个模块的协同——共享同一个事件图，但从中提取三个不同的信号用于三个不同的目的。

**支撑材料**：Phase 23、24、34、37、40、41、42 综合分析

### 6.2 未来展望

**写什么**：四个方向，每个方向 1–2 句：
- **表示层**：探索更丰富的边类型（如基于 LLM 推断的因果链和失败传播链）、图结构的自动化搜索（类似 NAS 的思路来自动选择边类型和权重）
- **遗忘层**：自适应阈值调度（根据当前存储压力和任务负载动态调整 θ₁/θ₂，而非固定阈值）、遗忘率的在线学习（从用户后续提问的频率和类型中学习哪些事件实际上更重要）
- **修正层**：多模态错误定位（同时利用文本嵌入和视觉特征进行嫌疑度计算）、跨 episode 的传播检测（当前仅检测同一 Goal 内的连续帧）
- **部署层**：将 GRAF-Mem 集成到真实机器人堆栈（如 ArmarX 框架）中，在实时交互中验证记忆维护的闭环效果——特别是修正模块在用户自然反馈（而非模拟 ground truth）下的表现
