# GRAF-Mem 反馈驱动修正模块

## 一、问题定义

层级情景记忆框架依赖视觉感知、场景图构建和 LLM 摘要三个步骤来将机器人经验转化为自然语言记忆。然而，这些步骤中任一环节的偏差——如视觉模型将"客厅"误识别为"厨房"、LLM 摘要遗漏关键动作或错误概括多步操作——一旦写入记忆树，便形成**持久化错误**。更严重的是，`EventBasedSummary` 的 `nl_summary` 属性从底层原始数据动态计算生成，无法通过简单赋值来修正。若系统不能更新错误记忆，则同一错误将在后续所有涉及该节点的问答中反复出现，形成**误差传播**。

因此，反馈驱动修正模块的目标是：在收到用户反馈或标准答案后，自动定位出错节点、生成修正后的摘要，并检测可能受同一错误影响的相邻节点，从而在单次修正请求中完成"从点到面"的错误修复。

---

## 二、方法设计

修正模块采用四阶段管线架构：错误定位、单点修正、错误传播检测与自动传播修正。为保护底层原始数据的完整性，修正操作不直接修改 `scenes` 或 `raw` 等底层字段，而是采用**摘要覆盖机制**——在节点对象上挂载 `_summary_override` 属性来覆盖原始摘要的展示和检索行为。

### 2.1 摘要覆盖机制

记忆树中所有消费摘要的位置——包括语义搜索的文本嵌入计算、Agent 交互式树展开时的节点展示——都遵循统一的优先级规则：若节点存在 `_summary_override`，则使用修正后的摘要；否则使用原始 `nl_summary`。该设计的关键优势在于：

- **可逆性**：`_original_summary` 同时保留原始版本，修正可回退
- **可追溯性**：`_correction_source` 记录修正来源，支持审计
- **非侵入性**：底层感知数据不受影响，不影响记忆树的 pickle 序列化核心结构

### 2.2 阶段一：错误定位

错误定位的目标是找到"哪个记忆节点的内容最可能导致了错误回答"。给定一个问题 $q$、系统的错误回答 $a_{\text{wrong}}$ 和正确的标准答案 $a_{\text{correct}}$，对记忆树中每个事件节点计算**嫌疑度分数**：

$$\text{suspicion}(n) = 0.6 \cdot \text{sim}(n, q + a_{\text{wrong}}) + 0.4 \cdot (1 - \text{sim}(n, q + a_{\text{correct}}))$$

其中 $\text{sim}(\cdot, \cdot)$ 为文本嵌入的余弦相似度。该公式的直觉是：一个节点如果与"错误信息"高度语义相关（高第一项），同时与"正确信息"语义距离较远（高第二项），则它最有可能是污染源。例如，对问题"机器人在哪个房间切了苹果"、错误答案"厨房"、正确答案"客厅"，包含"厨房+切苹果"但不含"客厅"信息的节点将获得最高嫌疑度。

所有事件节点按嫌疑度降序排列后，取前 $k$ 个（默认 $k=3$）作为候选修正目标。已修正过的节点（存在 `_summary_override`）自动跳过，避免重复修正。

### 2.3 阶段二：单点修正

对每个超过嫌疑度阈值的候选节点，使用 LLM 生成修正后的摘要。修正 LLM 接收四个输入：原始摘要、用户问题、错误答案和正确答案。Prompt 明确指示模型"只修改可能错误的部分，保留所有其他信息不变，只输出修正后的摘要文本，不含解释"。这种**最小化修正**策略避免了过度重写——修正目标是消除事实错误，而非替换整个摘要。

当 LLM 调用不可用或失败时，系统回退到**简单文本替换**：首先尝试在原始摘要中完整匹配错误答案并替换为正确答案；若无可匹配的完整片段，则提取错误答案与正确答案之间的差异词对（如"厨房"→"客厅"）进行局部替换。

修正完成后，调用 `apply_summary_override` 挂载覆盖属性，并清除节点的嵌入缓存以确保后续语义搜索重新计算向量。

### 2.4 阶段三：错误传播检测

记忆中的错误往往不是孤立的。如果视觉模型在时刻 $t$ 误识别了场景，那么时间上紧邻的事件节点（$t-1$、$t+1$ 等）很可能包含同样的误识别。错误传播检测从已修正节点出发，沿时间序列向前后各 $h$ 个邻居（默认 $h=2$）检查每个邻居的摘要与修正前错误摘要的余弦相似度。若相似度超过阈值（默认 $0.7$），则标记为疑似传播错误，并在节点上挂载 `_correction_hint` 元数据，记录传播路径和置信度。

### 2.5 阶段四：自动传播修正

对高置信度（相似度 $\geq 0.8$）的疑似传播错误，自动执行类比修正。有 LLM 时，向 LLM 展示"A 节点做了从 X 到 Y 的修正，请对相似的 B 节点做同样类型的修正"；无 LLM 时，从源修正中提取差异词对，在邻居摘要中执行相同的词级替换。

该阶段的理由是：如果两个节点的摘要文本高度相似，导致其中一个出错的原因很可能也同样影响了另一个。执行传播修正可以在**不需要额外反馈信号**的前提下扩大修正覆盖面。

## 三、评测协议

### 3.1 模拟反馈协议

标准评测流程为每道题创建独立的记忆树深拷贝（`deepcopy(history)`），题与题之间完全隔离，无法模拟"修正后的记忆影响后续问答"的真实使用场景。为此，设计了**模拟反馈协议**：

1. 同一 episode 内的所有问题共享同一份 history 对象（而非每题独立深拷贝）
2. 每道题回答后，调用 **Answer Judge** 判定答案质量
3. 若判定为 WRONG，以标准答案作为模拟用户反馈，触发完整修正管线
4. 修正后的 history（可能已修改了若干节点的摘要）直接用于该 episode 的下一道题
5. 下一道题因此受益于之前修正的累积效果

Episode 边界通过样本 ID 的前缀自动识别。TEACh 数据的样本 ID 格式为 `"{trial_ids}-{batch_idx}-{question_key}"`，其中 `question_key` 以 `rsplit('-', 1)` 剥离后即为 episode 标识。

### 3.2 Answer Judge 设计

Answer Judge 采用两阶段混合判定策略：

**阶段一（确定性快速判断）**：检查假设答案与标准答案之间是否存在精确匹配、子串包含或 token 序列包含关系。若任意条件满足，直接返回 CORRECT，无需调用 LLM。

**阶段二（LLM 语义判断）**：当阶段一无法确定时，调用独立的 Judge LLM 进行语义评估。Judge 输出三个标签之一：CORRECT（语义等价）、PARTIAL（部分正确，有关键遗漏或多余信息但无事实矛盾）、WRONG（明显矛盾或回答无关内容）。为避免误修正，只有 WRONG 触发修正管线；PARTIAL 被认为"不足以安全修正"。

### 3.3 评价指标

修正模块实验的主要评价指标分为三类：

**修正执行指标**：
- `direct_corrections`（直接修正数）：单点修正阶段实际应用了摘要覆盖的节点数，反映定位+修正的成功率
- `propagation_detections`（传播检测数）：被标记为疑似传播错误的邻居节点数，反映同一错误的影响范围
- `propagation_corrections`（传播修正数）：高置信度自动修正的节点数，反映"从点到面"的覆盖效果
- `suspects_checked`（嫌疑节点检查数）：错误定位阶段评估的候选节点总数

**问答质量指标**（沿用 GRAF-Mem 主实验的指标）：
- $S_c$（完全正确率）：回答在语义上完全命中标准答案的比例
- $S_p$（至少部分正确率）：CORRECT + PARTIAL 的比例，反映回答是否至少抓住了关键事实
- **Wrong / no-answer 率**：系统完全未能给出有效语义答案的比例

**行为变化指标**：
- **同 episode 内答案一致率**：修正运行与对照运行在同一题目上的答案文本逐条一致比例。越低说明修正协议对系统行为的影响越大
- **Judge 判定分布**：CORRECT / PARTIAL / WRONG 的分布，反映当前系统答案的整体质量和 Judge 的判定倾向

### 3.4 对照设计

为隔离"共享 history"和"主动修正"两个因素的各自贡献，设置两组对照：

- **共享 history 对照**：使用与修正实验完全相同的共享 history 协议，但跳过修正步骤（`correction_fn = None`）。该组剔除了主动修正的影响，单独量化"状态保持"的效应
- **标准独立评测**（现有 Phase 23–24 基线）：每题独立 `deepcopy(history)`。该组作为传统基线，量化整体协议切换的综合效应

## 四、实验结果

### 4.1 实验设置

| 实验 | 历史长度 | 配置 | 协议 |
|------|---------|------|------|
| Smoke 验证 | \|h\|=5 | 图增强 + 完整修正 | 共享 history + 修正 |
| 组 A（共享对照） | \|h\|=50 | 图增强 + correction.enabled=false | 共享 history + 无修正 |
| 组 B（完整修正） | \|h\|=50 | 图增强 + 完整修正 | 共享 history + 修正 |

所有实验使用 TEACh 测试集，每配置 10 个 batch × 10 种问题类型 = 100 题。Agent 使用 Gemini-2.5-Pro，Answer Judge 使用独立 Gemini-2.5-Pro 实例，嵌入模型使用 all-mpnet-base-v2。

### 4.2 修正执行统计

在 Smoke 验证（\|h\|=5）和完整修正运行（\|h\|=50）中，修正管线的**直接修正数、传播检测数和传播修正数均为 0**。根因分析如下：

| Judge 标签 | 判定数（\|h\|=50 组 B） | 占比 | 触发修正 |
|-----------|----------------------|------|---------|
| exact（精确匹配） | 3 | 3.1% | 否 |
| ground_truth_substring（标准答案是子串） | 7 | 7.3% | 否 |
| ground_truth_contained（token级包含） | 2 | 2.1% | 否 |
| llm_PARTIAL（LLM判为部分正确） | 85 | 88.5% | **否** |
| llm_WRONG（LLM判为错误） | 0 | 0.0% | 是 |
| llm_judge_error（Judge调用异常） | 1 | 1.0% | 否 |

Judge 的 96 次有效判定中，85 次（88.5%）为 PARTIAL，0 次为 WRONG。Answer Judge 保守的判定策略——"不确定时偏向 PARTIAL 而非 WRONG"——导致了修正管线在自然问答中从未被触发。这虽体现了安全设计理念，但也使得在正常评测条件下难以观测修正机制的主动效果。

### 4.3 共享协议的行为影响

尽管主动修正未被触发，共享 history 协议本身对系统行为产生了显著影响：

| 对比维度 | 组 A（共享无修正） | 组 B（共享+修正） |
|---------|-------------------|-------------------|
| 有效答案数 | 94/100 | 98/100 |
| 超时错误数 | 6 | 2 |
| 两组答案文本逐条一致率 | — | 60/100（**40% 答案不同**） |

组 A 与组 B 之间 40% 的答案差异并非由主动修正引起（修正从未触发），而是源于共享 history 协议下**记忆树展开状态的跨题保持**，叠加 LLM 非确定性（temperature=0.1，少样本 prompt）的共同效应。具体而言，前一道题在导航记忆树时展开和缓存了某些节点，后续题可以直接看到这些已展开的状态，从而改变了 Agent 的搜索路径和证据选择。

这一发现从侧面验证了反馈闭环的核心前提：**记忆状态的持续性本身就能显著改变系统的问答行为**。如果在此之上叠加主动修正——即不仅保持状态，还能修正错误信息——其影响的合理预期会比当前观测到的 40% 基线差异更大。

### 4.4 有效性与局限性分析

**已证明的能力**：
1. 修正管线代码已在完整评测链路上实现端到端验证（模块加载 → 嵌入计算 → Judge 调用 → 条件分支 → 修正管线入口），无运行时错误
2. 共享 history 协议导致 40% 答案变化，验证了有状态反馈闭环对系统行为的实质性影响
3. 摘要覆盖机制已正确集成到语义搜索和树节点展示两个关键消费端

**当前局限**：
1. Answer Judge 的策略过于保守，在自然问答中不会产生 WRONG 判定，无法触发主动修正
2. 缺少受控错误注入验证，无法在已知错误条件下定量评估各阶段的精度（定位准确率、修正准确率、传播覆盖率）
3. 修正协议不支持逐样本 checkpoint，长运行依赖一次性完成

## 五、后续工作：受控错误注入验证

鉴于自然问答中 WRONG 判定极少的现状，修正模块的定量验证应转向受控实验范式：

1. **定位精度验证**：在特定节点手动注入已知错误（修改 `_summary_override`），运行 `localize_error`，评估注入节点在嫌疑度排名中的位置
2. **修正质量验证**：对注入错误的节点调用 `correct_node_with_llm`，人工或 Judge 评估修正后的摘要是否消除了错误且保留了正确信息
3. **传播检测验证**：在同一 episode 的多个相邻节点注入相同错误模式，验证 `detect_error_propagation` 的召回率和精确率
4. **端到端验证**：运行完整的 `--enable-correction` 评测，使用错误注入后的 history，验证后续问题的回答是否因修正而改善

这种受控范式在论文中更适合作为机制级验证的强证据：它可重现、可量化、不依赖 Answer Judge 恰好产生 WRONG 判定的偶然性。

---

## 六、小结

反馈驱动修正模块为 GRAF-Mem 赋予了对长期记忆进行更新和维护的能力。它通过摘要覆盖机制实现非侵入式修正，通过四阶段管线覆盖从单点错误定位到邻域错误传播的完整修复链路，通过模拟反馈协议构建了可评估的闭环评测环境。当前实验虽未能触发主动修正，但验证了修正基础设施的完整性，并发现了共享状态本身对系统行为的显著影响。后续的受控注入实验将提供修正精度和效果的定量证据。
