# Active-H-EMV 毕设当前进度总结

## 一、课题目标与研究问题

本课题围绕长期机器人经验的情景记忆表示、检索与维护展开，研究对象是 H-EMV（Hierarchical Episodic Memory Verbalization）这一类面向机器人长期经验问答的层级记忆框架。

原始 H-EMV 的基本思想是：将机器人多轮、多天、跨任务的经历组织为一棵层级记忆树，让大语言模型在问答时按需展开和检索，以回答“过去做过什么”“在什么时候做的”“见过哪些物体”“为什么失败”等问题。

在实际研究中，我关注到原始 H-EMV 存在三个主要问题：

1. **横向语义关联不足**  
   原始树结构擅长表达“从原始感知到高层摘要”的纵向层级关系，但不擅长表达跨任务、跨时间、跨对象的横向关联。

2. **长期运行下记忆持续膨胀**  
   如果机器人持续运行，记忆树会不断增长，低效或冗余节点会稀释检索质量，并带来存储与上下文成本问题。

3. **错误写入后会持续传播**  
   一旦视觉理解、摘要生成或检索链路中出现错误，错误会被写入记忆，并在后续多个问题中持续影响回答。

因此，本课题的目标不是简单复现 H-EMV，而是在其层级记忆骨架上进一步构建一个**更主动、更可维护的长期情景记忆框架**，即：

- 能够更好地做横向联想检索；
- 能够在长期运行中进行记忆巩固与遗忘；
- 能够在接收到反馈后对记忆进行修正并抑制错误传播。

这也是项目命名为 **Active-H-EMV** 的原因，即从“被动存储式层级记忆”走向“主动可维护情景记忆”。

## 二、项目的主要研究内容

围绕上述问题，我目前把整个项目的研究内容划分为三条主线：

### 1. 图增强检索主线

在原始层级树之外，构建一个基于事件节点的记忆图，用图结构补足树结构横向语义弱的问题。图用于支持：

- 时间相邻事件的联想；
- 共享物体的跨任务联想；
- 共位置或共场景事件的联想；
- 相似动作或相似操作模式的联想；
- 更复杂的因果性扩展。

最终目标是让系统在回答长期经验问题时，不只依赖向量相似度检索，而是能够利用“图邻居扩展 + 联合重排”的方式，把真正相关但文本上不完全相似的历史事件召回出来。

### 2. 遗忘与记忆巩固主线

针对长期运行时记忆树不断膨胀的问题，我设计并实现了一个基于记忆效用的渐进式遗忘机制。其核心思路是：

- 重要、近期、独特的记忆完整保留；
- 次重要的记忆删除底层重数据（如图像、声音）但保留摘要；
- 更低效用的记忆进一步压缩为更轻量的摘要保留形式；
- 对失败经历、用户对话等关键记忆设置保护规则，避免误删。

这条主线的重点不是简单“删历史”，而是研究如何在**压缩存储与保留问答能力之间做权衡**。

### 3. 反馈驱动修正主线

针对记忆一旦生成就冻结的问题，我实现了一个闭环记忆修正机制。其目标是：

- 根据用户反馈或标准答案定位错误节点；
- 用摘要覆盖方式修正错误内容；
- 让修正后的内容能够立即影响后续检索和问答；
- 进一步检测同类错误是否沿时间邻接或相关事件传播。

这条主线的意义在于把长期记忆系统从“只会累积历史”推进到“能够在反馈中自我修正”。

## 三、项目的主要创新点

目前本课题的创新点可以概括为以下三项。

### 创新点一：在层级情景记忆树基础上引入事件关联图，实现图增强检索

与原始 H-EMV 只依赖层级树不同，我在不破坏原有树结构的前提下，从事件层自动派生记忆图，并构造多类型边，包括：

- 时间相邻边；
- 共享物体边；
- 共位置边；
- 相似动作边；
- 可选因果边。

在检索阶段，不再只做“语义相似度 top-k”，而是采用：

- 语义种子召回；
- 图邻居扩展；
- 图分数与语义分数联合重排。

这一创新点的核心价值是：**让系统具备跨时间、跨任务、跨对象的横向联想能力**。

### 创新点二：提出基于效用的渐进式遗忘机制，用于长期记忆维护

在遗忘模块中，我将长期记忆维护建模为效用评估问题。节点效用综合考虑：

- 时间新近性；
- 语义独特性；
- 结构重要性；
- 用户对话与失败状态等特殊信号。

然后按效用值执行三级遗忘：

- Level 0：完整保留；
- Level 1：删除图像/声音等重感知数据；
- Level 2：压缩为摘要保留。

同时，我进一步引入图度中心性作为结构重要性信号，使“记忆图”不仅服务于检索，也服务于记忆巩固和遗忘决策。

### 创新点三：提出反馈驱动的记忆修正机制，抑制错误在长期记忆中的传播

修正模块的关键创新在于：

- 不直接破坏底层原始数据，而是通过摘要覆盖机制修正错误记忆；
- 让修正内容立即参与后续搜索和展示；
- 结合局部判断与 LLM Judge，减少误触发修正；
- 在单点修正之外，进一步检测时间邻近节点中的潜在错误传播。

其本质是为长期机器人记忆增加了一个“反馈闭环”，使系统不再只是静态存储，而具备一定的自我修复能力。

## 四、当前已经实现的主要模块

截至目前，项目核心模块都已经实现，且大多已完成基础验证或正式实验验证。

### 1. 原始 H-EMV 层级记忆骨架

已保留并复用了原始 H-EMV 的多层记忆结构，包括：

- L0 原始多模态瞬时经验；
- L1 场景图；
- L2 事件摘要；
- L3 目标摘要；
- L4 更高层生活片段摘要。

对应系统已经能够支持：

- 按层级展开历史；
- 搜索相关记忆节点；
- 用 LLM 回答关于过去经验的问题。

### 2. 图构建模块

已完成事件图的自动构建，支持：

- 从事件节点派生图节点；
- 构建多种边类型；
- 构建图缓存；
- 在问答时将图作为检索增强结构使用。

### 3. 图增强检索模块

已实现真实的图增强检索机制，而不是仅做简单 re-ranking。当前系统已经支持：

- 基础向量召回；
- 图邻居扩展；
- 联合候选池重排；
- 子树递归检索时图参数透传；
- 不同查询意图下激活不同类型边。

### 4. 结构化 guardrail 与问答稳定性模块

为了解决长期历史问答中无效搜索、空回答和 token 失控的问题，已增加多种结构化工具与护栏，例如：

- `task_list`
- `task_lookup`
- `object_lookup`
- `event_date_lookup`
- temporal neighbor 辅助查找
- checkpoint / resume / retry-errors
- prompt token 上限与平均上限控制

这些机制主要服务于工程稳定性和评测可控性。

### 5. 遗忘与记忆巩固模块

已实现：

- 效用函数；
- 三档遗忘策略；
- 免疫规则；
- 随机遗忘基线；
- 图中心性引导遗忘版本；
- 面向 ARMARX_LT_MEM 的本地压缩与审计工具。

### 6. 反馈修正模块

已实现：

- 错误定位；
- 摘要覆盖；
- 搜索与展示对覆盖摘要的感知；
- 本地快速判断 + LLM semantic judge 触发策略；
- 错误传播检测；
- 模拟反馈评测接口。

## 五、当前已经完成的实验验证

目前实验已经分成两大部分完成：

1. **TEACh 数据集上的图增强检索主实验**
2. **ARMARX_LT_MEM 上的遗忘模块机制验证实验**

### （一）图增强检索模块：已完成正式主实验验证

在 TEACh 长历史问答实验中，我已经完成了多轮 smoke、diagnostic、pilot 和 formal 实验，并最终跑出了可用于论文主结果表的正式结果。

目前最关键的正式结果如下：

#### `|h| = 50` 正式结果

| 方法 | Valid | `S_c` | `S_p` | `T` |
| --- | ---: | ---: | ---: | ---: |
| H-EMV baseline few-shot | 96.0% | 41.0 | 27.0 | 27.63K |
| Graph-H-EMV zero-shot | 100.0% | 43.0 | 23.0 | 5.19K |
| Graph-H-EMV few-shot | 98.0% | 44.0 | 23.0 | 16.15K |

从这个结果可以看出：

1. 图增强版本在 `|h|=50` 上相对 baseline 有语义正确率提升；
2. zero-shot 图增强版本的 token 成本远低于 few-shot baseline；
3. 图增强不仅提升了回答质量，也显著改善了检索效率。

#### `|h| = 100` 正式结果

目前已经完成 baseline 的正式跑满结果：

| 方法 | Valid | `S_c` | `S_p` | `T` |
| --- | ---: | ---: | ---: | ---: |
| H-EMV baseline zero-shot | 90.0% | 42.0 | 27.0 | 7.08K |
| H-EMV baseline few-shot | 95.0% | 38.0 | 21.0 | 29.85K |

另外，当前 Active-H-EMV 在 `|h|=100` 的正式评测中，也已完成 100 QA 的跑满结果，关键指标为：

- valid = 98.0%
- `S_c = 49.0%`
- `S_p = 75.0%`
- `T = 2.29K`

这一结果说明，当前系统在更长历史条件下已经具有较强的竞争力，并相对原文基线表现出明显优势。

### （二）问答稳定性与工程可控性：已完成多轮诊断实验

为了保证系统不仅“能跑”，而且“跑得稳、可控、可复现”，我已经完成了多轮 h=15 / h=50 的诊断实验。主要效果包括：

1. **空回答、重复搜索和 token runaway 问题已显著缓解**
2. **checkpoint/resume/retry-errors 工作流已经跑通**
3. **结构化 task/date/object 工具已经在 targeted case 中验证有效**
4. **缓存审计和预构建机制已经建立**

例如：

- h=15 诊断集中已经做到 `valid = 100%`
- h=50 / h=100 正式评测已完成缓存补齐与 100 QA 跑满
- 平均 prompt token 已经被控制在一个明显优于原始 few-shot baseline 的水平

### （三）遗忘模块：已完成机制实现与分层验证

在遗忘模块这条线上，我没有停留在“代码实现”，而是已经推进到了较完整的机制验证阶段。

目前已完成的验证包括：

#### 1. 树结构压缩验证

在 ARMARX_LT_MEM 上，遗忘模块已经能真实压缩记忆树结构。  
例如 `ubpf_ultra` 可以将文件大小压缩到基线的大约 `0.797`。

#### 2. one-pass 长度统计验证

我进一步验证了遗忘后的历史在 one-pass flatten 条件下是否变短。结论是：

- 遗忘确实会缩短输入；
- 但下降幅度有限；
- 说明遗忘模块不能单独解决 full-history flatten 的长上下文问题。

这一点帮助我厘清了论文表述边界：  
**遗忘模块的主价值在树结构维护，而不是单独解决 one-pass 长上下文。**

#### 3. 关键证据保真审计

我对 117 个高细节密度事件做了结构审计，结果如下：

| Setting | Matched Events | L0 | L1 | L2 | Mean Scenes / Event | Mean Relations / Event |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `base` | 117 | 117 | 0 | 0 | 47.31 | 145.44 |
| `random_medium` | 117 | 102 | 6 | 9 | 45.01 | 137.20 |
| `medium` | 117 | 71 | 23 | 23 | 39.74 | 112.63 |
| `medium_graph` | 117 | 71 | 36 | 10 | 43.89 | 130.22 |
| `ultra` | 117 | 66 | 27 | 24 | 39.58 | 111.82 |

这个结果说明：

- `medium_graph` 比 `medium/ultra` 更能保留 relation-rich 事件的结构细节；
- 随机遗忘不是简单“删少一点”或“删多一点”，而是表现不稳定；
- 图中心性引导遗忘更适合在压缩与细节保真之间做平衡。

#### 4. 局部低层细节切片实验

为了进一步验证这些结构差异是否真的影响问答，我构造了一个 `local detail slice`，只给模型局部 scene graph，而不是整棵历史。

在前 4 个 relation-sensitive probe 上，结果为：

| Setting | Hit Count |
| --- | ---: |
| `base` | 4 / 4 |
| `random_medium` | 3 / 4 |
| `medium` | 0 / 4 |
| `medium_graph` | 4 / 4 |
| `ultra` | 0 / 4 |

这一结果非常关键，因为它表明：

1. 遗忘设置之间的差异不仅存在于“结构统计”里；
2. 这种差异已经能够被传递到 relation-sensitive 局部 QA 上；
3. `medium_graph` 明显优于 `medium/ultra`；
4. `random_medium` 的行为不稳定，进一步说明“忘什么”比“忘多少”更重要。
