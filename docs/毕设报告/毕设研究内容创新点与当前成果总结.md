# 毕设研究内容、创新点与当前成果总结

## 一、课题背景与总体目标

本课题围绕**长期机器人经验的情景记忆表示、检索与维护**展开，核心目标是在原始 H-EMV（Hierarchical Episodic Memory Verbalization）框架基础上，构建一个更主动、更可维护、更适合长期运行的情景记忆系统，即 **Active-H-EMV**。

原始 H-EMV 的优势在于：它能够把机器人的长期经历组织为一棵多层级记忆树，使大语言模型可以通过“逐层展开 + 按需检索”的方式回答关于过去经历的问题，例如：

- 过去做过什么任务；
- 在什么时候做的；
- 见过哪些物体；
- 某次失败发生的原因是什么。

但是在进一步研究和复现实验的过程中，我发现原始 H-EMV 仍存在三个核心不足：

1. **横向语义关联能力不足**  
   层级树结构擅长表示“从原始感知到高层摘要”的纵向关系，但不擅长表达跨任务、跨时间、跨对象的横向联系。

2. **长期运行下记忆持续膨胀**  
   如果机器人长期运行，记忆树会不断增长，底层细节和冗余节点会增加存储压力，并降低检索效率与回答质量。

3. **错误写入后缺乏修正机制**  
   一旦摘要、感知或检索结果中存在错误，这些错误会被固化到记忆中，并在后续多个问题中持续传播。

因此，本课题的总体目标可以概括为：

> 在保留 H-EMV 层级情景记忆骨架的前提下，引入图增强检索、效用引导遗忘和反馈驱动修正三种主动机制，构建一个可检索、可巩固、可修正的长期机器人情景记忆系统。

## 二、整个项目的研究内容

围绕上述目标，本项目的研究内容主要分为三条主线。

### 1. 图增强检索

该部分研究的核心问题是：

> 原始层级树只能依靠节点摘要文本来检索历史，是否可以引入图结构，利用事件之间的时间、物体、位置和动作关联来增强检索？

为此，我在原始层级记忆树之外，构建了一个**事件级记忆图**，并将其用于问答时的候选扩展与重排。这样系统不仅能根据文本相似度找到相关节点，还可以通过图邻接关系召回“文本不完全相似、但实际上与问题相关”的历史事件。

### 2. 遗忘与记忆巩固

该部分研究的核心问题是：

> 当机器人长期运行时，是否可以在尽量不损伤问答能力的前提下，对较旧或较低效用的记忆进行压缩？

为此，我设计了一个**基于记忆效用的渐进式遗忘机制**。它不是简单删除历史，而是根据节点的重要性、新近性、独特性和结构地位，对记忆执行不同强度的保留或压缩。

### 3. 反馈驱动修正

该部分研究的核心问题是：

> 当记忆中已经存在错误时，系统是否能够根据反馈对其进行修正，并尽量阻止错误继续影响后续问答？

为此，我实现了一个**摘要覆盖式的记忆修正机制**。它能够在不破坏底层原始数据的前提下，对错误摘要进行修正，并让修正后的内容立即参与后续搜索和问答。

## 三、项目的主要创新点

当前整个项目的创新点可以概括为以下三项。

### 创新点一：提出图增强的层级情景记忆表示与检索机制

与原始 H-EMV 只依赖树结构不同，本项目引入了一个从事件节点自动派生的记忆图，并在其中构造多类型关联边，包括：

- 时间相邻边（temporal adjacent）；
- 共享物体边（co-object）；
- 共位置边（co-location）；
- 相似动作边（similar-action）；
- 可选因果边（causal）。

在检索时，不再只做简单的 embedding 相似度 top-k，而是采用如下流程：

1. 先做语义种子召回；
2. 再做图邻居扩展；
3. 最后将语义分数与图结构分数联合重排。

这个创新点解决的是原始层级树“横向语义联想能力弱”的问题。它使得系统可以跨任务、跨对象、跨时间地联想相关事件，从而更适合长期经验问答。

### 创新点二：提出基于效用的渐进式遗忘机制

本项目不是把“遗忘”理解为简单删除历史，而是将长期记忆维护建模为**压缩-保真权衡问题**。

我设计的遗忘模块对每个事件节点计算效用值，综合考虑：

- 新近性（recency）；
- 语义独特性（uniqueness）；
- 结构重要性（importance）；
- 用户对话、失败经历等关键保护信号。

在此基础上，系统执行三级遗忘：

- Level 0：完整保留；
- Level 1：删除图像/声音等重感知数据，但保留文本语义；
- Level 2：进一步压缩为摘要保留。

更重要的是，我还把**图度中心性**引入到重要性估计中，使图结构不仅服务于检索，也参与记忆巩固和遗忘决策。

### 创新点三：提出反馈驱动的闭环记忆修正机制

针对记忆一旦生成就冻结的问题，我实现了一个闭环修正机制，其特点包括：

- 错误节点定位；
- 最小化摘要修正；
- 摘要覆盖而非破坏原始数据；
- 搜索与展示对修正摘要的即时感知；
- 基于时间邻近性的错误传播检测。

其本质是为长期情景记忆增加了一个反馈闭环，使系统从“只会累积历史”发展为“能够在反馈中自我修正”。

- L2：事件级摘要；
- L3：目标级摘要；
- L4：高层生活片段摘要。

系统已经支持：

- 层级展开；
- 语义搜索；
- 长期历史问答。

### 2. 图构建模块

## 五、当前已经完成的主要实验验证

目前实验验证已经覆盖了两大重点方向：

1. **TEACh 数据集上的图增强检索正式实验**
2. **ARMARX_LT_MEM 上的遗忘模块机制实验**

修正模块则已经完成机制实现与基础验证，但量化规模仍可进一步补强。

### （一）图增强检索：已完成正式主实验

当前图增强检索是整个项目中最成熟、最完整的一条实验主线。

#### `|h| = 50` 正式结果

| 方法 | Valid | `S_c` | `S_p` | `T` |
| --- | ---: | ---: | ---: | ---: |
| H-EMV baseline few-shot | 96.0% | 41.0 | 27.0 | 27.63K |
| Graph-H-EMV zero-shot | 100.0% | 43.0 | 23.0 | 5.19K |
| Graph-H-EMV few-shot | 98.0% | 44.0 | 23.0 | 16.15K |

从该结果可以得出两个重要结论：

1. 图增强检索在 `|h|=50` 上相较 baseline 有语义正确率提升；
2. 图增强 zero-shot 配置大幅降低了平均 prompt token 成本。

这说明图增强不是简单“加更多上下文”，而是在更高效地召回相关证据。

#### `|h| = 100` 正式结果

当前已完成的关键结果包括：

- baseline 的 `|h|=100` 正式结果；
- 当前 Active-H-EMV 在 `|h|=100` 上跑满 100 QA 的正式结果。

其中当前系统的关键指标为：

- valid = 98.0%
- `S_c = 49.0%`
- `S_p = 75.0%`
- `T = 2.29K`

这一结果说明当前系统在更长历史条件下已经具有较强表现，并明显优于原始基线水平。

### （二）问答稳定性与工程可控性：已完成多轮诊断实验

为了保证系统不仅“有方法”，而且“能稳定运行”，我已经完成了多轮 h=15 / h=50 / h=100 的 smoke、diagnostic 和 formal 实验。

当前已经验证的效果包括：

1. checkpoint / resume / retry-errors 已经跑通；
2. 长历史缓存预构建和缓存审计机制已经建立；
3. 结构化 task/date/object 工具已经在 targeted case 中证明有效；
4. 空回答、重复搜索和 token runaway 问题已显著缓解。

从工程层面讲，这意味着项目已经不是“概念可行”，而是形成了较完整、可复现实验工作流。

### （三）遗忘模块：已完成机制实现与较完整验证

遗忘模块这条线当前已经不只是“做了代码”，而是推进到了机制验证层面。

#### 1. 树结构压缩验证

在 ARMARX_LT_MEM 上，遗忘模块已经能够真实压缩记忆树。

例如：

- `ubpf_ultra` 可将文件大小压缩到基线的大约 `0.797`

这说明遗忘模块已经在存储层面产生实际效果。

#### 2. one-pass 长度统计验证

我进一步验证了：

> 遗忘后的树在 one-pass flatten 条件下，输入是否会变短？

结论是：

- 会变短；
- 但下降幅度有限；
- 说明遗忘模块不能单独解决 full-history flatten 的长上下文问题。

这一结论帮助我明确了论文叙事边界：遗忘模块更适合被表述为**树级压缩与信息保真机制**，而不是单独解决 one-pass token 问题的方法。

#### 3. 关键证据保真审计

我对 117 个高细节密度事件做了结构层面的审计，结果如下：

| Setting | Matched Events | L0 | L1 | L2 | Mean Scenes / Event | Mean Relations / Event |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `base` | 117 | 117 | 0 | 0 | 47.31 | 145.44 |
| `random_medium` | 117 | 102 | 6 | 9 | 45.01 | 137.20 |
| `medium` | 117 | 71 | 23 | 23 | 39.74 | 112.63 |
| `medium_graph` | 117 | 71 | 36 | 10 | 43.89 | 130.22 |
| `ultra` | 117 | 66 | 27 | 24 | 39.58 | 111.82 |

这一结果说明：

1. `medium_graph` 比 `medium/ultra` 更能保留 relation-rich 事件的结构信息；
2. 图中心性引导遗忘在压缩与细节保真之间提供了更好的平衡；
3. 随机遗忘并不稳定。

#### 4. 局部低层细节切片实验

为了进一步验证“这些结构差异是否真的会影响问答”，我构造了一个只使用局部 scene graph 的小型 `local detail slice`。

在前 4 个 relation-sensitive probe 上，结果如下：

| Setting | Hit Count |
| --- | ---: |
| `base` | 4 / 4 |
| `random_medium` | 3 / 4 |
| `medium` | 0 / 4 |
| `medium_graph` | 4 / 4 |
| `ultra` | 0 / 4 |

这说明：

1. 不同遗忘设置之间的差异不仅存在于结构统计里；
2. 这种差异已经能够传递到 relation-sensitive 局部 QA 上；
3. `medium_graph` 明显优于 `medium/ultra`；
4. `random_medium` 体现出不稳定性，支持“忘什么比忘多少更重要”的结论。
