# Role
You are a world-class academic illustration expert specializing in high-quality architecture figures for top-tier computer vision, robotics, and artificial intelligence papers such as CVPR, NeurIPS, ICLR, and ICRA.

# Task
Design a professional academic architecture figure for a method named Active-H-EMV: an active hierarchical episodic memory verbalization framework for long-term robot experience question answering. The figure should clearly show how the method extends the original H-EMV tree memory with a memory graph, graph-augmented retrieval, utility-based memory consolidation, and feedback-driven correction. The final figure should look like a clean overview figure from a top-tier AI paper.

# Visual Constraints
1. Overall Style
   - Use a professional top-conference paper style: clean, modern, minimal, rigorous, and highly readable.
   - Use flat vector illustration aesthetics, similar to polished DeepMind or OpenAI research diagrams.
   - Use thin, crisp lines, rounded rectangles, simple graph nodes, and clear directional arrows.
   - Background must be pure white.
   - Avoid cartoon style, oil painting style, photorealistic rendering, noisy decorative elements, and heavy shadows.

2. Color Palette
   - Use soft pastel colors and low-saturation tones.
   - Suggested palette:
     - light blue for hierarchical memory;
     - soft teal for the memory graph;
     - pale green for graph-augmented retrieval;
     - muted yellow for memory consolidation and forgetting;
     - soft coral for feedback correction;
     - light gray for raw data and external input/output.
   - Avoid bright red, bright green, neon colors, dark heavy colors, or saturated gradients.

3. Text Rules
   - All text inside the figure must be in English.
   - Use short labels only. No long sentences or paragraphs inside the figure.

     - "Feedback-Driven Correction"
     - "LLM Agent"
     - "Natural-Language Answer"

# Methodology to Visualize
The method starts from long-term robot experience streams, including visual observations, actions, object states, task goals, and user utterances. Following the H-EMV paradigm, these experiences are organized into a hierarchical episodic memory tree:

- L0: Raw Experience
- L1: Scene Graph
- L2: Event Summary
- L3: Goal Summary
- L4: High-Level Summary

The original H-EMV tree provides vertical temporal abstraction and interactive expansion, but it has three limitations: weak lateral semantic association, unbounded memory growth, and error propagation when incorrect summaries are stored.

Active-H-EMV keeps the hierarchical tree as the backbone and derives an additional memory graph from event-level summaries. Each event summary is a graph node. Edges encode cross-event relations such as temporal adjacency, co-object relation, co-location relation, similar action relation, and optional causal relation. This memory graph is the central structure of the method and should be visually emphasized with the label "One Graph, Three Uses".

The memory graph supports three active mechanisms:

1. Graph-Augmented Retrieval
   - A user query is first processed by semantic seed retrieval.
   - Initial seed nodes are retrieved from the memory tree.
   - The memory graph expands these seeds to graph neighbors.
   - The expanded candidate pool is jointly re-ranked.
   - The LLM agent interactively reads the selected tree nodes and produces a natural-language answer.
   - Include the compact pipeline labels:
     "Seed Retrieval" -> "Graph Expansion" -> "Joint Re-ranking" -> "LLM Agent".
   - Include a compact scoring label:
     "Score = Semantic + Graph + Depth".

2. Utility-Based Consolidation
   - The system periodically evaluates event utility.
   - Utility combines recency, uniqueness, and importance.
   - Include the compact equation:
     "U(n) = alpha Recency + beta Uniqueness + gamma Importance".
   - Low-utility memory is progressively compressed.
   - Use three small levels:
     "Retain", "Detail Removal", "Summary Only".
   - Show that graph centrality contributes to importance.

3. Feedback-Driven Correction
   - After an answer is produced, an answer judge compares the hypothesis with the expected or user-corrected answer.
   - Only clearly wrong answers trigger correction.
   - The system localizes suspicious memory nodes, applies summary override, and optionally detects propagated errors.
   - Include the compact labels:
     "Answer Judge", "Error Localization", "Summary Override", "Propagation Check".
   - Show a feedback arrow from the answer side back to the memory tree and memory graph.

Create a single wide landscape architecture figure, suitable for a paper method overview.

Suggested layout:

   - Place the phrase "One Graph, Three Uses" near the graph as a central conceptual label.

4. Top-right: Online retrieval branch
   - From "User Query", draw arrows through:
     "Seed Retrieval" -> "Graph Expansion" -> "Joint Re-ranking" -> "LLM Agent" -> "Natural-Language Answer".
   - Use pale green module boxes.
   - Connect "Graph Expansion" to the central memory graph.
   - Connect "LLM Agent" back to the hierarchical memory tree to show interactive tree access.

5. Bottom-center: Offline consolidation branch
   - Draw a periodic loop from the memory tree and memory graph into:

   - Include the equation:

   - Then show three progressive outcomes:

6. Bottom-right: Feedback correction branch

7. Overall framing
