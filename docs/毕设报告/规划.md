# Active-H-EMV 本科毕设完成计划清单

## 1. 总体目标与当前状态

目标是在约 6 周内完成一个“稳妥毕业”版本：代码仓库状态可解释、核心创新点有真实实现和基础验证、实验结果足够支撑论文论证、论文正文和答辩材料完整闭环。

当前已完成内容：

- 已恢复 `active-h-emv` 环境，TEACh 数据集与基础数据流转已跑通。
- 已实现并验证原 H-EMV 层级记忆基础框架。
- 已实现图增强记忆结构与图增强检索，包括图构建、多类型边、邻居扩展与联合重排。
- 已实现记忆巩固与遗忘模块，包括效用函数、三级遗忘、免疫规则。
- 已实现闭环反馈修正模块，包括错误定位、摘要覆盖、传播检测、混合 Judge 触发策略。
- 已修复关键逻辑问题：无条件修正、子树检索参数丢失、answer 格式清理、checkpoint/resume、空回复处理。
- 已形成阶段记录文档 `docs/record/phase*.md`。
- 已有可用实验基础：Graph `|h|=50 zs` 达到 `S_c=43, S_p=23, T=5.2K`；Graph pilot 与 baseline 对比显示 `S_c` 有提升。
- 已发现当前主要风险：API 网关不稳定、在线摘要隐藏 token 成本、相对日期问题检索效率较低、部分 smoke 未跑满。

## 2. 六周推进清单

### 第 1 周：冻结工程主线与实验口径

- 整理当前未提交代码，按功能分组提交：
  - 检索与 REPL 稳定性修复。
  - checkpoint/resume/token budget 评测框架。
  - phase 记录文档与 smoke 结果。
- 清理实验目录：
  - 保留正式结果、可解释 smoke、阶段记录。
  - 移除明显错误、中断、无解释价值的旧 metrics 中间文件。
- 固化实验口径：
  - `|h|` 表示一段长历史中的基础情景数量，不等于 `--n-samples`。
  - 标准论文表格每个 `|h|` 应为 100 QA。
  - BLEU/ROUGE 只作为辅助指标，主指标使用 `S_c`、`S_p`、`T`、有效回答率。
- 更新 `docs/record/index.md` 或同等记录入口：
  - 列出每个 phase 的目的、结果、结论、下一步。
- 不再默认跑 `h>=25`；任何 `h=25/50/100` 新实验前先确认预算与必要性。

### 第 2 周：修完低风险高收益工程问题

- 增加结构化日期查询工具：
  - 新增 `date_lookup(date_or_relative)` 或等价 API。
  - 支持 exact date、exact time、N days ago 问题。
  - 目标是减少 `history.expand(date)` 后继续多轮搜索的 token 消耗。
- 完善 temporal neighbor：
  - 保留当前 `temporal_neighbor()`。
  - 加入更清晰日志：target candidate、before/after sibling、score、recommended answer。
- 控制 VQA 误触发：
  - 若摘要已足够回答时间/任务问题，禁止自动进入 VQA。
  - 仅在问题明确询问视觉属性且已有 leaf image 时调用 VQA。
- 处理在线摘要隐藏成本：
  - 明确区分“预构建 history summary”和“问答时在线生成 summary”。
  - 评测前优先预构建或复用缓存，避免正式实验中临时生成大量摘要。
- 保持每次修改后运行：
  - `python -m py_compile` 覆盖修改文件。
  - h=5 或 h=15 的 2-5 样本 smoke。

### 第 3 周：完成小规模稳定性实验

- 使用 `data/teach/test_set_15.pkl` 做调参主集。
- 先跑小规模：
  - h=15，`n-samples=5`，验证无重复检索、无异常 VQA、无隐藏 token 激增。
  - h=15，`n-samples=15`，验证 checkpoint/resume、失败重试、token budget。
- 若稳定，再补 h=15，`n-samples=50`：
  - 只在 token 均值健康、API 稳定时继续。
  - 若 API 空回复或连接错误较多，只 retry failed，不重跑成功样本。
- 输出一份 h=15 诊断报告：
  - 有效回答率。
  - 平均 prompt token。
  - 最大 prompt token。
  - 空回复数量。
  - Connection error 数量。
  - temporal/date/object 问题典型案例。
- 本周不追求论文最终大表，重点是证明系统稳定和优化方向有效。

## 3. 待实现/待完善的关键工程任务

- `date_lookup()`：结构化处理 exact date、exact time、N days ago，减少多轮展开。
- Summary cache/precompute：正式实验前预构建长历史摘要，避免在线摘要隐藏成本。
- Graph retrieval logging：记录 seed、expanded neighbor、edge type、score，服务论文案例。
- Failure retry workflow：只重试 `###ERROR###`、空回答、connection error，不重复烧成功样本。
- Metrics cleanup：主输出保留 `S_c/S_p/T/valid_rate`，BLEU/ROUGE 降级为辅助。
- Record discipline：每次实验后写 `docs/record/phaseX_*.md`，包括命令、结果、异常、结论。

## 4. 实验计划与验收标准

### 小规模开发实验

- h=5 或 h=15，`n-samples=2/5`。
- 目标：
  - 不出现循环搜索。
  - 不出现明显无效 VQA。
  - 单题 prompt 不超过 8K，异常样本不超过 15K。
  - 失败样本可 checkpoint 后 retry。

### h=15 稳定性实验

- 使用 `data/teach/test_set_15.pkl`。
- 先跑 `n-samples=15`，稳定后再考虑 `n-samples=50`。
- 目标：
  - 有效回答率不低于 90%。
  - 平均 prompt token 控制在 5K 内。
  - Connection/empty reply 单独统计，不混入方法错误。
  - temporal/date/object 问题有可解释日志。

### 正式论文实验

- 优先复用已有 h=50/h=100 结果。
- 新跑 h=25 及以上前必须确认预算。
- 论文主表至少包含：
  - H-EMV baseline。
  - Graph-enhanced H-EMV。
  - Active-H-EMV 当前完整或近完整版本。
- 主指标：
  - `S_c`：完全正确率。
  - `S_p`：部分正确率。
  - `T`：每题平均 prompt token，单位 K。
  - Valid answer rate：有效回答率。
- 验收：
  - 每个表格数字可追溯到结果文件。
  - 每个结果文件有对应命令记录。
  - 不使用未跑满或中断结果作为正式主结论，除非明确标为 pilot。

## 6. 风险与默认策略

- API 额度不足：
  - 默认不跑大规模新实验。
  - 使用已有正式结果 + 小规模补充实验。
- API 网关不稳定：
  - 使用 checkpoint/resume。
  - 只 retry failed samples。
  - 把 connection error 与模型错误分开统计。
- token 成本异常：
  - 立即暂停。
  - 检查是否在线构建 summary。
  - 优先修缓存，不继续硬跑。
- 指标提升不大：
  - 不夸大结论。
  - 强调图增强的可解释召回、效率趋势和主动记忆维护框架。
- 模块来不及全量大实验：
  - 图增强作为主量化贡献。
  - 遗忘和修正作为机制实现 + smoke/case study 支撑。
- 论文时间不足：
  - 优先保证正文完整、实验可追溯、答辩讲得清楚。

- 排期按约 6 周设计。
- 后续默认不跑 `h=25` 及以上实验，除非用户明确确认。
- BLEU/ROUGE 不作为核心贡献指标。
- 每次关键实验或设计变化后都要写入 `docs/record/`，防止上下文漂移。
